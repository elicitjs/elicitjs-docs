# Probe

<Lead>`pick: "probe"` previews an edit before it commits. Moving the pointer draws an uncommitted ghost, and `getData()` reports only the last settled answer. A staged probe edit advances to the next [stage](/editing/stages) when it commits.</Lead>

<ApiReference entries={api} />

<Section id="preview" title="Ghost proposals">

`pick: "probe"` splits an edit into preview and commit. As the pointer moves, the marks draw an inert **ghost** of what a commit would produce.

The proposal applies to the dataset, so every mark reading those rows shows the ghost. `getData()` and `onChange` stay unchanged until you commit.

<Example
  code={probeASingleValue}
  title="Probe a single value"
  blurb="move({ pick: 'probe' }) displays a ghost knob that settles on click or drag release."

/>

</Section>

<Section id="commit-modes" title="Two ways to commit">

A probe edit commits on either gesture:
1. **Move, then click**: move the pointer without pressing to place the ghost, then click to settle it.
2. **Grab and drag**: press on the mark, drag to the value, and release.

</Section>

<Section id="stages" title="Probe across stages">

A probe edit with a `stage` advances to the next stage when it commits, unless it sets `advance: false`. See [Stages](/editing/stages) for the stage API.
