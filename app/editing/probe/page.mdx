# Probe & stages

<Lead>`pick: "probe"` previews an edit before it commits. Moving the pointer draws an uncommitted ghost, and `getData()` reports only the last settled answer. Stages split a question into steps: first do X, then do Y. Give an edit a numeric `stage` and it is active only in that stage; an edit with no `stage` is always active. Move between stages with `nextStage()`, `setStage(n)` and `getStage()`, and listen with `on("stage", cb)`. A staged probe edit advances to the next stage when it commits.</Lead>

<Section id="preview" title="Ghost proposals">

`pick: "probe"` splits an edit into preview and commit. As the pointer moves, the marks draw an inert **ghost** of what a commit would produce.

The proposal applies to the dataset, so every mark reading those rows shows the ghost. `getData()` and `onChange` stay unchanged until you commit.

<Section id="commit-modes" title="Two ways to commit">

A probe edit commits on either gesture:
1. **Move, then click**: move the pointer without pressing to place the ghost, then click to settle it.
2. **Grab and drag**: press on the mark, drag to the value, and release.

</Section>

<Section id="basics" title="Stages: place, then size">

Stage 0 drags the point along `x` (where). Stage 1 resizes it (how confident). Only one edit is live at a time.

A staged probe edit advances the stage when it commits. Set `advance: false` on it to advance by hand instead.
