# Selection

<Lead>The selection is the set of rows currently picked. It is **interface state**, kept beside the data. `edit.select()` makes a mark selectable, and selected rows get the `selected` effect. An edit that needs a row to write to, such as a legend picker or an external control, reads the selection. The answer data is unchanged.</Lead>

<ApiReference entries={api} />

<Section id="what-it-is" title="State, not data">

The selection stays out of `getData()`, fires no `change` and takes no undo step. It survives edits and resets when you call `setData` or advance a stage. It reports through its own `select` event.

`edit.select()` is a direct-pick click. A plain click selects one row and clears the rest. Clicking the selected row again deselects it.

<Section id="feedback" title="Seeing the selection">

Selected rows get the `selected` [effect](/effects). By default it traces each mark's edge in a deep shade of its own colour. It applies to every mark over that row, so selecting a bar also outlines its label. Restyle it on the spec:

```js
effects: { selected: { outline: { color: "#2563eb", width: 3 } } }
```

`selected` outranks `hovered`, and `grabbed` outranks `selected`, so a row you are dragging shows as grabbed.

</Section>

<Section id="multi" title="Selecting several rows">

`edit.select({ multi: true })` makes shift-click (or meta-click) add to the selection. Shift-clicking a selected row removes it. A plain click still replaces the whole selection. Use `exclusive: false` to make every click add, with no modifier.

An edit that writes the selected row writes **all** selected rows, so one swatch click recategorises the whole selection.

<Section id="external" title="Driving it from outside">

An external call and a click set the selection the same way. The selection belongs to the dataset, so [charts that share a dataset](/dataset#history) show one selection. See [External controls](/editing/external-controls#selection) for the related API.

```js
chart.select(2);                                 // replace with row 2
chart.select([0, 2]);                            // replace with rows 0 and 2
chart.toggleSelection(3);                        // add or remove row 3
chart.selectAll();
chart.selectWhere("group", "North", { all: true });   // a whole category
chart.clearSelection();

chart.getSelection();                            // 0  (the first, or null)
chart.getSelectionAll();                         // [0, 2]
chart.on("select", (first, all) => …);
```

`selectWhere` takes the first match by default. Pass `{ all: true }` for every row of a category, which is usually what a control that names a value wants.

</Section>

<Section id="targets" title="Edits that read the selection">

A gesture that carries no row of its own reads the selection. A [legend](/editing/legend) picker is the main case: a swatch names a *value*, so its `row` defaults to the selection.

The swatch that matches the selection is ringed. With nothing selected and more than one row, a picker has no target and no ring. In a one-row table, the picker writes that row. If nothing in the chart can select, a warning says the picker has no target.

</Section>
