# External controls

<Lead>Drive an edit from a control outside the interface: a `<select>`, a slider, a rotate icon or a plain function. Give the edit a `name`, then call `el.control(name).set(value)`. The control synthesises the **same** events a pointer does, so constraints, undo/redo, guides and `on("change")` behave the same.</Lead>

<ApiReference entries={api} />

<Section id="how" title="Name an edit, then drive it">

An edit maps a gesture to data by *inverting* a channel's scale. `control(name).set(value)` runs that scale *forward* to find the gesture, then runs the ordinary edit. A value edit (`set`, `editText`) takes the value directly, with no pixel step. `control(name).accepts()` reports what the channel's scale allows, so a picker or slider can offer only valid values.

</Section>

<Section id="scatter" title="A picker and a drag pad">

The `<select>` writes the point's category through a `set()` edit. Its options come from `control("category", 0).accepts().values`. The pad drives a two-axis `move` live, and `begin() … set({x,y}) … end()` is one undo entry. The `clamp` on `y` limits the pad exactly as it limits a mouse drag.

<Section id="pick" title="Pick vs. cycle: driving other gestures">

`.set(value)` drives the value edits (`set`, `editText`) and the positional ones (`move`, `rotate`, `resize`). The click edits (`cycle`, `remove`, `toggle`) take no value. `.fire()` drives them by running the edit's own gesture on the row. One circle can offer a **picker** (`set`, to jump to a value) and a **cycle** (`fire`, to step to the next) on the same field, beside the native click.

</Section>

<Section id="face" title="Sliders for facial features">

Each facial parameter is a channel. Bind it to a field with a named `set()` edit and a slider can write it. The face stays draggable: grab the mouth to pull a smile. Each slider's range comes from `control(field).accepts().domain`.

<Section id="rotate" title="A rotate icon for a box">

`rotate` reads a pointer angle about the mark. `control("spin", 0).set(deg)` encodes the angle to the pointer position that would produce it, then runs the ordinary rotate edit. The box also rotates by direct drag.

<Section id="plane" title="Sweep and nearest edits">

`control(name, index)` names its row, so it also drives an edit whose pick only chooses a row: `nearest` and `sweep`. `.set(v)` writes row `index`, whichever row the pointer would have found. An edit that needs a pointer path or position, such as `edit.line.draw()`, a brush or `create()`, logs a warning and writes nothing. Drive those with `el.emit({ type, x, y })` in plot pixels.

<Section id="selection" title="Driving the selection">

The selection is interface state, kept beside the data, so it has its own API and its own `select` event. `el.select(index)` picks a **specific row**. `el.selectWhere(field, value)` picks by **category**: the first matching row, or every match with `{ all: true }`. Both set the selection as a click with `edit.select()` does. The selected row gets the highlight outline, and a legend picker edits it. `on("select")` reports the change. `getData` and `on("change")` stay silent, because no answer data changed.

Pass an array to `el.select` for several rows at once. See [Selection](/editing/selection) for multi-select, the `selected` effect and the edits that read the selection.

<Section id="domain" title="Driving a domain">

`el.setDomain(field, domain)` writes a field's domain from outside the chart, for a zoom button or a "reset view" control. It commits like [`edit.axis.zoom()`](/editing/zoom) and `edit.axis.pan()`: one undo step, a `change` notification, and every scale updates. Pass `null` to restore the domain declared in the schema.

```js
chart.setDomain("x", [20, 40]);   // zoom to 20–40
chart.setDomain("x", null);       // back to the declared domain
```

See [Zoom & pan](/editing/zoom#wheel) for buttons that zoom in, zoom out and reset.

</Section>
