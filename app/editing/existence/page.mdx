# Row lifecycle & lock

<Lead>Manage dataset membership and permissions. `create()` inverts clicked pixels to append new rows, `remove()` deletes rows on modifier clicks, and `lock` protects given ground truth from accidental edits.</Lead>

<ApiReference entries={api} />

<Section id="what-can-create" title="What can — and cannot — be created">

Creation writes dataset **rows**, so it belongs on a data mark positioned by an invertible axis. Only **guides** (which have no per-row data) and **derived** marks (computed from the whole dataset, like `trend`) are excluded.

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th>Mark</th><th>Create?</th><th>How</th></tr>
    </thead>
    <tbody>
      <tr><td><code>point</code> · <code>dot</code> · <code>symbol</code></td><td>✓</td><td>Invert pointer through x and y</td></tr>
      <tr><td><code>tick</code> · <code>bar</code></td><td>✓</td><td>One axis inverts to a band slot, the other to value</td></tr>
      <tr><td><code>rect</code></td><td>✓</td><td>Seed default extents (<code>x1</code>/<code>x2</code> or <code>y1</code>/<code>y2</code>)</td></tr>
      <tr><td><code>composite</code> (glyph)</td><td>✓</td><td>Create on one component mark; row renders across all</td></tr>
      <tr><td><code>line</code> · <code>path</code></td><td>✓</td><td>Series-aware anchor and draw edits</td></tr>
      <tr><td><code>rule</code> · <code>axis</code> · <code>grid</code></td><td>✗</td><td>Guides edit the domain schema, not data rows</td></tr>
      <tr><td><code>trend</code></td><td>✗</td><td>Derived regression fit over all rows</td></tr>
    </tbody>
  </table>
</div>

</Section>

<Section id="create" title="Create — click to add">

`create()` listens on empty space to invert pointer coordinates and append a new row. Constraints (such as `count({ max })`) cap the total allowed dataset size.

Declare a creator on exactly one mark so a single click mints one row.

<Example
  code={clickToAddAPoint}
  title="Click to add a point"
  blurb={"create({ defaults }) mints a datum at the pointer; count({ max: 8 }) caps the dataset."}
  try={(
    <>
      <b>Click</b> empty space to add a point · <b>drag</b> to move it.
    </>
  )}
/>

</Section>

<Section id="lock-seed" title="Locked seed data, free additions">

Some dataset rows are baseline facts rather than elicited beliefs. Setting `lock: "seed"` locks all initially supplied rows as read-only. Any row added through `create()` remains fully editable.

<Example
  code={scatterObservedPointsYours}
  title="Observed points + elicited additions"
  blurb="Grey points are locked seed data; new additions are interactive."
  try={(
    <>
      <b>Click</b> empty space to add a point · <b>drag</b> your point. Grey seed points never move.
    </>
  )}
/>

</Section>

<Section id="lock-predicate" title="Locking rows by predicate">

Pass a predicate function to lock rows based on their fields (for example, separating historical actuals from future forecasts).

<Example

</Section>

<Section id="you-draw-it" title="You draw it (locked record + multi-stage reveal)">

In the classic New York Times "You Draw It" paradigm (e.g. 1968–1990 actuals vs. 1991–2016 predictions):
1. **`lock: "seed"`** locks historical data so dragging over the given years cannot change them.
2. **`edit.line.draw({ stage: 0 })`** enables drawing the missing years during stage 0.
3. **`chart.nextStage()`** advances to stage 1, retiring the edit and displaying the answer key guide.

<Example
  code={drawTheLineForTheMissingYears}
  title="Draw the line for the missing years"
  blurb="The historical line (1968–1990) is locked. Draw 1991–2016, then advance the stage to reveal the true record."
  try={(
    <>
      <b>Drag</b> across the empty half to draw 1991–2016, then press <b>Show me how I did</b> to reveal the answer key.
    </>
  )}
/>

</Section>
