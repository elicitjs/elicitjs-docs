# Scales & channels

<Lead>A **data type** says what a field _is_: `quantitative`, `categorical`, `ordinal` or `temporal`. You declare it once, on the [schema](/schema). A **scale type** says how a channel _draws_ it: `linear`, `log`, `band`, `ordinal`, and so on. The scale type is normally **derived**. A categorical field on a bar’s x is a band, because a bar needs an interval; on a dot’s x it is a point, because a dot sits on a tick. When you do name a scale, `scale` takes a name, a spec, or a live d3 scale. Every positional scale is invertible, which is what makes editing possible.</Lead>

Nothing below names a scale. The schema says `cat` is categorical and `n` is quantitative; the bar says it needs an interval for discrete data. Band and linear fall out. Swap `bar` for `point` and x becomes a point scale, with no other change.

<Section id="zero-crossing" title="Crossing zero — symlog & diverging">

Elicited quantities are often _differences_: a revision, an error, a surprise. They can span orders of magnitude in both directions. `log` is undefined at 0 and below, and a `sequential` ramp has no reference point. `symlog` is linear near zero and logarithmic beyond it. `diverging` colours by distance from a pivot, scaling each side on its own.

<Section id="override" title="Naming a scale: by name, by spec, by d3">

`scale` takes three forms: a name (log x), a spec (a sqrt size range), or a d3 scale (a band with custom padding). A d3 scale is used as built. A positional d3 scale with no range gets the plot’s pixel range. It keeps its padding and stays invertible, so the drag works.

<Section id="ordered-colour" title="Ordered data gets an ordered ramp">

Colour follows the field's data type as well as its scale. `categorical` values are unordered, so they get distinct hues. `ordinal` values run low to high, so they get a **ramp sampled to one swatch per category**, light to dark, in order. A Likert scale then reads as a scale rather than as four unrelated colours.

Declare the difference and the colour follows:

```js
agree: { type: "ordinal",     domain: ["disagree", "neutral", "agree", "strongly agree"] }
team:  { type: "categorical", domain: ["north", "south", "east"] }
```

Use `categorical` for a group identifier, even when you list its values in an order. A series key is unordered.

</Section>

<Section id="two-encodings-colour" title="Two encodings on one channel">

A scale belongs to one **encoding**: a (channel, field) pair. Two marks colouring by *different* fields get two scales, each with its own domain and legend. They also get different scheme **families**, so the two stay perceptually distinct.

Two marks colouring by the *same* field share one scale, one set of colours, and one legend, so a shared colour means a shared value.

</Section>

<Section id="categorical-position" title="Categorical position → point scale">
