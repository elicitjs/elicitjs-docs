# Guides

<Lead>A guide draws the **rule** and the **state**: what a gesture is allowed to do, and what is left to do. It views the interface's state rather than rows, so it has no channels, no table and no `edit`, and writes no data. Declare one in `guides: [...]` (`guides.rule`, `guides.region`, `guides.image`, `guides.remaining`, `guides.proximity`, `guides.tip`, `guides.crosshair`, `guides.custom`), or let an edit draw its own with `guide:`. Survey widgets use their own [widget guides](#widget-guides). Guides rebuild every render and let every gesture pass through. For hovered, selected and grabbed feedback, see [Effects](/effects).</Lead>

<ApiReference entries={api} />

<Section id="two-kinds" title="Which kind you want">

The two differ in who declares them.

**`guide:` on an edit** draws the edit's own rules. It already knows the channel, the scale and the constraints that gate it, so you repeat none of them. Use it to show what a gesture is allowed to do.

**`guides: [...]` on the spec** draws an annotation you choose — a target line, a shaded range — from whatever you compute out of the guide context.

Use the edit-owned form when the edit already knows what you want to draw. A `guides.rule` at a `clamp` limit restates that limit in a second place, and the two can drift apart.

</Section>

<Section id="edit-bounds" title="An edit draws its own rules">

`guide: true` on an edit turns on `bounds` and `catchment`. You repeat nothing from the constraints: the edit draws every dataset constraint whose `field` matches its own channel.

Bounds follow the edit's axis. The same `clamp` draws horizontal lines on a y-edit and vertical ones on an x-edit.

  title="clamp and snap, drawn by the edit"
  blurb="guide: true draws the allowed band and a labelled line at each clamp limit."
  try={(
    <>
      <b>Drag</b> a bar past a limit, or between the snap stops.
    </>
  )}
/>

</Section>

<Section id="remaining" title="What is left to do">

`guides.remaining()` states how much of a budget is still unallocated — the count a reader needs while placing tokens or splitting a total.

```js
guides.remaining({ field: "y", unit: "token" })   // "3 tokens left"
guides.remaining({ field: "y", total: 100 })      // "45 of 100 left"
```

Pass no `total` and it reads the target from the chart's own `maintainSum` constraint, so the number you enforce and the number you show cannot drift apart. Set `unit` for the countable phrasing, `anchor` (`"top-right"` by default) for the corner, and `label` for a function of `(remaining, used, total)` when you want your own wording.

<Example
  code={howMuchIsLeftToAllocate}
  title="A budget with its remainder"
  blurb="guides.remaining reads the target from the maintainSum constraint, so the budget is written once."
  try={(
    <>
      <b>Drag</b> a bar — the count updates as the total moves.
    </>
  )}
/>

</Section>

<Section id="parts" title="Restyling the parts">

`guide: true` is shorthand for the parts at their defaults. Pass an object to switch and restyle each one.

A `snap`'s stops draw as short ticks at the plot edge, where the axis also sits. Raise `bounds.tickLength` and `bounds.tickOpacity` to pull them clear of it.

**`bounds`** draws the constraint boundaries: a `clamp`'s band and limits, a `snap`'s stops, a `maintainSum` cap. On with `guide: true`.

**`catchment`** draws the radius in which a proximity pick resolves a free pointer to a mark. On with `guide: true`. Edits that select a target (`pick: "nearest"`, `pick: "sweep"`, `brushSpan`, `brushRect`, `edit.geo.brush`) also turn catchment on when you **omit** `guide`. Set `guide: false` to turn it off.

**`track`** draws where a handle can travel, for handles whose range isn't a scale. Off by default — turn it on where that range isn't obvious from the mark, as on [a face's parameters](/marks/face#track).

Each part takes `color`, `dash`, `width` and `opacity`; `bounds` adds `bandOpacity`, `fontSize`, `tickLength` and `tickOpacity`. A `color` on the guide itself sets all three parts at once. Theme tokens live at `theme.guide.bounds|catchment|track` (and `theme.constraint.color`).

<Example
  code={restylingTheParts}
  title="One colour, or one per part"
  blurb="Left sets one colour for every part. Right styles each separately and lengthens the snap ticks."
  try={(
    <>
      <b>Move</b> near a dot to see the catchment ring, then <b>drag</b> it into the band.
    </>
  )}
/>

</Section>

<Section id="annotations" title="Rule and region">

Annotations you declare in `guides: [...]`. `guides.region` shades a band, `guides.rule` draws a reference line. Both position in data space through the same scales a mark uses, so they stay put as points move.

<Example
  code={aTargetBandWithARule}
  title="A target band with a rule"
  blurb="guides.region shades 40–60; guides.rule marks the midpoint."
  try={(
    <>
      <b>Drag</b> a dot in and out of the target band.
    </>
  )}
/>

</Section>

<Section id="image" title="An image behind the marks">

`guides.image({ src })` draws a picture behind the gridlines and marks, as a CSS background image on the plot. With no `x` or `y` it fills the plot, which makes it the chart's background. Give `x: [lo, hi]` and `y: [lo, hi]` in data units to place it, and it moves with the scales. Unset, either axis spans the plot.

`fit` defaults to `'fill'`: the picture stretches to its box, so a position on it reads in the same units as the axes. `fit`, `position` and `repeat` take the same values as on the [`image` channel](/marks/image#settings), so `fit: 'none', repeat: 'repeat'` tiles a texture. `opacity` fades it.

<Example
  code={aFloorPlanToPlaceThingsOn}
  title="A floor plan to place things on"
  blurb="guides.image spans 40 × 30 m, so each point's x and y are metres on the plan."
  try={(
    <>
      <b>Drag</b> the router and the speaker to where you would put them.
    </>
  )}
/>

For a picture per row, or one inside a mark, see [Image](/marks/image).

</Section>

<Section id="live" title="Guides derived from the data">

Every option takes a literal or a function of the guide context (`{ data, scales, features, ui, width, height, stage }`), so an annotation can read the rows it annotates. Here one rule is a fixed target and the other is the running **mean**. Guides rebuild each render, so it recomputes on every commit. The band tracks the spread the same way.

<Example
  code={aMeanLineThatChasesTheBars}
  title="A mean line that chases the bars"
  blurb={"guides.rule({ y: ({ data }) => d3.mean(data, (d) => d.y) }) reads the dataset."}
  try={(
    <>
      <b>Drag</b> a bar. The fixed target holds; the mean line and the band follow.
    </>
  )}
/>

</Section>

<Section id="tips" title="Tooltips">

`tip: true` on any mark shows a tooltip of the row under the pointer: one `column: value` line per column. Pass a list of columns (`tip: ["city", "rain"]`) to show only those, or a function of the row (`tip: (d) => string`) for your own wording.

A tip is a guide, so gestures pass through it: drag a bar while its tooltip is showing. It also shows on read-only rows, such as a locked seed or a [context row](/editing/existence#context).

<Example
  code={aTipOnEveryBar}
  title="A tip on every bar"
  blurb="tip: true on a barY with move(). The tooltip follows the pointer; the drag works underneath."
  try={(
    <>
      <b>Hover</b> a bar to read it · <b>drag</b> it while the tip is showing.
    </>
  )}
/>

`guides.tip()` is the long form. `text` takes the columns or a function of the row returning a string or an array of lines. `anchor: "mark"` pins the box beside the mark's centre instead of the pointer, and `mark` limits it to the mark with that `id`. `format` sets how numbers print, as a d3 format specifier or a function.

<Example
  code={aTipInYourOwnWords}
  title="A tip in your own words"
  blurb={"guides.tip({ anchor: \"mark\", text: (d) => [...] }) writes two lines beside the point."}
  try={(
    <>
      <b>Hover</b> a point to read its share · <b>drag</b> it up or down.
    </>
  )}
/>

</Section>

<Section id="crosshair" title="Crosshair">

`guides.crosshair()` draws dashed rules through the pointer across the plot. Each rule reads the value under the pointer off its axis, at the plot's bottom and left edges. Set `x: false` or `y: false` to draw one rule, and `readout: false` to drop the labels. `format` sets how the readouts print.

The rules hide when the pointer leaves the plot. Gestures pass through them.

<Example
  code={aCrosshairWithReadouts}
  title="A crosshair with readouts"
  blurb={"guides.crosshair({ format: \".1f\" }) reads hours and score under the pointer."}
  try={(
    <>
      <b>Move</b> over the plot to read both axes · <b>drag</b> a point to an exact value.
    </>
  )}
/>

</Section>

<Section id="widget-guides" title="Widget guides">

The [widgets](/widgets) draw their chrome with guides you can also use in your own spec:

- `guides.prompt(text, { y })` draws the question in the top margin.
- `guides.options({ labelOffset, radius, control })` draws a choice's options, one per category, in the theme's [design](/widgets#designs): rings and labels by default.
- `guides.cellGrid({ pad })` draws a matrix's cells and headers.
- `guides.sliderTrack({ format })` draws a slider's track with end labels.
- `guides.quadrants({ x, y })` draws centred axes with a label at each end.

Each reads its colours from `theme.widget`.

</Section>
