# Guides

<Lead>A guide draws the **rule** and the **state** — what a gesture is allowed to do, and what is left to do. It views chart state rather than rows, so it has no channels, no table and no `edit`, and can never write data. Declare one in `guides: [...]` (`guides.rule`, `guides.region`, `guides.remaining`, `guides.proximity`, `guides.custom`), or let an edit draw its own with `guide:`. Guides rebuild every render and never capture a gesture. For feedback on interaction state — hovered, selected, grabbed — see [Effects](/effects).</Lead>

<ApiReference entries={api} />

<Section id="two-kinds" title="Which kind you want">

The two differ in who declares them.

**`guide:` on an edit** draws the edit's own rules. It already knows the channel, the scale and the constraints that gate it, so you repeat none of them. Use it to show what a gesture is allowed to do.

**`guides: [...]` on the spec** draws an annotation you choose — a target line, a shaded range — from whatever you compute out of the guide context.

Reach for the edit-owned form when the thing you want to draw is already known to the edit. A `guides.rule` at a `clamp` limit restates that limit in two places, and the two drift apart.

</Section>

<Section id="edit-bounds" title="An edit draws its own rules">

`guide: true` on an edit turns on `bounds` and `catchment`. You repeat nothing from the constraints: the edit draws every dataset constraint whose `field` matches its own channel.

Bounds follow the edit's axis. The same `clamp` draws horizontal lines on a y-edit and vertical ones on an x-edit.

<Section id="remaining" title="What is left to do">

`guides.remaining()` states how much of a budget is still unallocated — the count a reader needs while placing tokens or splitting a total.

```js
guides.remaining({ field: "y", unit: "token" })   // "3 tokens left"
guides.remaining({ field: "y", total: 100 })      // "45 of 100 left"
```

Pass no `total` and it reads the target from the chart's own `maintainSum` constraint, so the number you enforce and the number you show cannot drift apart. Set `unit` for the countable phrasing, `anchor` (`"top-right"` by default) for the corner, and `label` for a function of `(remaining, used, total)` when you want your own wording.

<Example

</Section>

<Section id="parts" title="Restyling the parts">

`guide: true` is shorthand for the parts at their defaults. Pass an object to switch and restyle each one.

A `snap`'s stops draw as short ticks at the plot edge, where the axis also sits. Raise `bounds.tickLength` and `bounds.tickOpacity` to pull them clear of it.

**`bounds`** draws the constraint boundaries: a `clamp`'s band and limits, a `snap`'s stops, a `maintainSum` cap. On with `guide: true`.

**`catchment`** draws the radius in which a proximity pick resolves a free pointer to a mark. On with `guide: true`. Proximity picks that select a target (`nearest`, `sweep`, brush*) also turn catchment on when you **omit** `guide` — set `guide: false` to silence it.

**`track`** draws where a handle can travel, for handles whose range isn't a scale. Off by default — turn it on where that range isn't obvious from the mark, as on [a face's parameters](/marks/face#track).

Each part takes `color`, `dash`, `width` and `opacity`; `bounds` adds `bandOpacity`, `fontSize`, `tickLength` and `tickOpacity`. A `color` on the guide itself sets all three parts at once. Theme tokens live at `theme.guide.bounds|catchment|track` (and `theme.constraint.color`).

<Section id="annotations" title="Rule and region">

Annotations you declare in `guides: [...]`. `guides.region` shades a band, `guides.rule` draws a reference line. Both position in data space through the same scales a mark uses, so they stay put as points move.

</Section>

<Section id="live" title="Guides derived from the data">

Every option takes a literal or a function of the guide context (`{ data, scales, features, ui, width, height, stage }`), so an annotation can read the rows it annotates. Here one rule is a fixed target and the other is the running **mean**. Guides rebuild each render, so it recomputes on every commit. The band tracks the spread the same way.
