# Authoring SDK

<Lead>Extend Elicit.js with new marks, edits and gestures. Marks use `authoring.encodeChannel` and `resolveStyle`. Edits use `authoring.makeEdit` and `invertChannel`. Multi-event lifecycles register with `authoring.registerDriver`. Edits go on a channel (`y: { field, edit: move() }`) or in a mark's `edits: [...]`. For the model these extend, see [Core concepts](/concepts). For the stock edits, see [Editing](/editing).</Lead>

<Section id="custom-mark" title="A custom mark">

A mark is a view over the chart’s dataset. The factory returns a feature object, and its only required method is `build(data, scales, width, height)`.

- Call `normalizeMarkOptions` first.
- Resolve every channel through `encodeChannel` and `resolveStyle`.
- Spread `authoring.markCommon(opts)` to pass `id`, `edits`, `table`, `tip` and `clip` through unchanged.
- Set `discreteScale` when discrete data needs a band or a point scale.
- Set `type` on the feature. Every feature carries one; the example uses `"square"`.
- Leave mark-wide `pointerEvents` to the engine.

To let a datum’s [derived channels (`{ fn }`)](/concepts#derived) see their row index and the dataset, pass the optional `index` and `data` arguments when you resolve per datum: `authoring.resolveStyle(scales, channels, d, defaults, i, data)`.

<Section id="edit-ladder" title="The edit ladder">

Reach for the smallest tool that fits:

1. **Stock edit** — `move`, `resize`, `create`, … when the behaviour already exists.
2. **`custom(fn)`** — one-off `apply`, same gesture/pick defaults.
3. **`makeEdit(spec)`** — full descriptor control (`type`, `pick`, `cardinality`, `name`, …).
4. **`registerDriver`** — multi-event lifecycle / a new `pick` value.

`apply` is pure: return a new datum, a new array, or `undefined`. Prefer `invertChannel` over hand-rolled `scale.invert`.

<Section id="apply-array" title="When apply returns a full array">

Most edits return one datum, which replaces the row at `index`. Whole-dataset edits, such as reorder, create and remove, return a new array. `rank()` is the built-in example: drag swaps discrete rank slots.

<Section id="drivers" title="Register a driver">

Stock `pick` values (`direct`, `nearest`, `plane`, `probe`, `sweep`, …) cover most lifecycles. For a new one, register a driver. An edit reaches a driver by naming it, as in `pick: "clickNearest"`, and each edit reaches exactly one driver. `wants(edit)` claims an edit by capability, such as a relative slide, and doesn't re-test `pick`.

`onEvent` handles hover, click and drag. `runEdit` and `previewEdit` commit or preview through the same constraint and undo path as stock edits. Declare `sessionKeys`. Every driver on the mark shares the per-feature session, and the `session.clear()` you receive nulls only your keys. Declare `options` for any setting your driver reads off the edit, or the engine reports it as an unknown option. Set `selects: true` if `guide: true` should draw a snap ring. Set `targetsRow: true` if the driver only chooses a row, so that `chart.control(name, index)` can run its edits on a given row.

<Section id="glyphs" title="Glyphs: prefer a group of marks">

If a glyph’s handles map to distinct fields of a row, build it as a [`composite`](/marks/composite): ordinary marks over the same rows. Direct picks then keep each handle to its own field. Use `node.channel` with a `when` guard only when several handles must live on one feature over one datum, because their positions are derived rather than stored as fields.

Put a whole-dataset plane gesture (`create`, `rotate`, …) on exactly one mark. Two marks with the same plane edit fire twice per click.

</Section>

<Section id="helpers" title="Helpers to reuse">

Reuse these for proximity and minting:

- `invertChannel` / `recenterSpan` / `markCenter`: pointer ↔ data for positional edits
- `schemaDefaults(schema)`: mint a row with every field set to its default (or `null`)
- `authoring.nextSeriesKey(data, seriesField, schema?)`: the next free series id for a new line
- `nearestMark` / `nearestSeries` / `nearestMarkOnAxis`: shared distance pickers

To restyle the built-in [widgets](/widgets), register a design: [`authoring.registerDesign`](/widgets#new-design).

For a custom edit that creates rows, set `cardinality: "append"` so constraints know which row is new. For an edit that runs the pointer back through a scale, set `inverts: true` so the dead-drag guard can check the channel. To drive an edit from external UI, give it a `name` and call [`chart.control(name)`](/editing/external-controls).

</Section>
