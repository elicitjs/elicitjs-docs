# Composite

<Lead>A composite is a glyph: a group of ordinary marks over the chart's one dataset. Each part encodes some fields of the same rows, and a part whose channel carries an `edit` is a handle. Give a part a `frame:` channel and the composite becomes a box its parts sit inside; `group` is an alias of `composite`.</Lead>

<Section id="lollipop" title="Lollipop — drag the tip">

A stem (a span rule from the baseline to the value) plus a draggable tip. Two marks: the `ruleX` draws the stem and carries no edit, so it is inert; the `point` is the handle and edits `value`. Drag a tip and its stem re-derives, because both marks read the same row.

<Section id="error-bar" title="Error bar — move the dot, resize the interval">

Three editable fields on one row: `mean` (the dot), `lo` and `hi` (the caps). Each is a separate mark, so each edits a plain `y` channel and dragging a cap moves only that end — no handle arbitration to write. The whisker is a `ruleX` spanning lo..hi; it follows the caps because it reads the same rows.

<Section id="plus" title="Composite channels + per-part channels">

Two layers of binding. **Composite** `channels` (here `x`, `y`, `angle`) trickle into every part so the glyph shares one position and one orientation. **Each part** still declares its own channels and shorthands — arm length, stroke colour, a hub’s `fill` / `size`. A part key wins on conflict. Inherited `edit`s attach to the last part only, so one `rotate()` spins the whole glyph without double-applying.

<Section id="creating" title="Creating a whole glyph at once">

Creation is [mark-agnostic](/editing/existence#what-can-create): a plane gesture mints one row, and every part of the glyph encodes it — so one create makes a whole composite appear. The rule that a whole-dataset edit belongs on **exactly one mark** is what makes this clean: put `create` on a **single part** (here the tip), and a click appends one row, not one per part. The inert stem re-derives from the same row, so the stem and tip show up together.

<Section id="box" title="A glyph with its own units">

The parts above sit on the chart's axes. Some glyphs need the opposite: a face's eye is 16% of the way up *the face*, not at `y = 0.16` of the data.

Give a part a `frame:` channel and the composite becomes a **box**. Its own `x` / `y` / `size` set that box's centre and half-size for each row, and `frame:` values are read inside it:

- `x` / `y` — `[-1, 1]` from the centre, y up. `{ frame: -0.4 }` is 40% of the way to the left edge.
- `size` / `rx` / `ry` / `strokeWidth` — `[0, 1]`, a fraction of the half-size.
- `angle` / `curvature` — the channel's own units. The scale belongs to its own part, so two parts can take opposite ranges.
- `{ field: "f", frame: [lo, hi] }` maps the field's schema domain onto that slice of the box. The domain stays on the schema.

`x` / `y` / `size` describe the box, so they don't trickle into the parts. A part that states no position sits at the centre. `{ value }` still means pixels, so use `frame:` for anything that should scale with the glyph.

<Section id="why-scales" title="Why they're real scales">

A `frame:` channel is a real scale, built once per row. So the ordinary edits work inside a box unchanged: `move`, `slide`, `rotate` and `resize` invert a gesture back through the same mapping that placed the part, and `.accepts()` reports the field's real range to an [external control](/editing/external-controls).

A `frame:` channel is also invisible to the chart's axes. An eye at `{ frame: -0.4 }` never widens the x domain or adds an axis for coordinates that aren't in the data's units.

</Section>

<Section id="scaling" title="Everything scales together">

A part's geometry is a fraction of the box, so resizing the glyph resizes its contents. An edit on an inner part still writes its own field on its own domain.

An edit on the composite's own `x` / `y` / `size` moves or resizes the whole glyph. The box covers the glyph, so you can grab it anywhere, including between the parts. A part carrying its own edit takes the drag first.

<Section id="parts" title="What box mode returns">

The box first, then the parts, all as plain marks. The box carries the composite's `x` / `y` / `size`, so those fields still build the chart's axes; a composite with no edit on them draws nothing you can grab.

Two limits apply to a part placed in the box:

- A `{ fn }` channel is called once per row, as `(d, 0, [d])`, so it can't look across rows. Read the field instead.
- A line-family mark can't span rows inside a box. Position it on the global scales, or move it out of the composite.

A part with no `frame:` channel keeps the global scales, so one part of a glyph can still span to a data value.

</Section>

<Section id="face" title="Build a face with one brow">

[`face()`](/marks/face) is a composite in box mode: a `point` head, two [`ellipse`](/marks/ellipse) eyes, two `tickY` brows and a [`curveY`](/marks/curve) mouth. It's a preset, so you can assemble a different anatomy from the same parts — here, one brow instead of two.

The brow and the mouth are both [`curve`](/marks/curve) marks. `curvature` is the apex's offset from the chord, as a fraction of the half-chord, so it scales with the glyph. Positive curvature bows to the left of travel, which arches a rightward chord upward. A descending `frame:` range reverses that, so a rising `grump` dips the brow and a rising `mood` deepens the smile.
