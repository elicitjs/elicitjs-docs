# Composite

<Lead>A composite is a glyph: a group of ordinary marks, its `parts`, over the same rows of the dataset. Each part encodes some fields, and a part whose channel carries an `edit` is a handle. Give a part a `frame:` channel and the composite becomes a box that its parts sit inside.</Lead>

<Section id="lollipop" title="Lollipop">

A lollipop is a stem plus a draggable tip. The stem is a `ruleX` spanning the baseline to the value. It carries no edit, so it is inert. The tip is a `point` that edits `value`. Drag a tip and its stem re-derives, because both marks read the same row.

<Section id="plus" title="Composite channels + per-part channels">

Channels bind at two levels. The composite's `channels` (here `x`, `y`, `angle`) pass down to every part, so the glyph shares one position and one orientation. Each part still declares its own channels and shorthands: arm length, stroke colour, a hub's `fill` and `size`. A part's key wins on conflict. Inherited `edit`s attach to the last part only, so one `rotate()` spins the whole glyph once.

<Section id="creating" title="Creating a whole glyph at once">

A create gesture mints one row, and every part of the glyph encodes it, so one click adds a whole composite. See [what can be created](/editing/existence#what-can-create). Put `create` on one part only (here the tip). A click then appends one row, not one per part. The inert stem re-derives from the same row, so the stem and tip appear together.

<Section id="box" title="A glyph with its own units">

The parts above sit on the chart's axes. Some glyphs need their own units: a face's eye sits 16% of the way up *the face*, not at `y = 0.16` in the data.

Give a part a `frame:` channel and the composite becomes a **box**. The composite's `x` / `y` / `size` set each row's box centre and half-size, and `frame:` values are read inside that box:

- `x` / `y`: `[-1, 1]` from the centre, y up. `{ frame: -0.4 }` is 40% of the way to the left edge.
- `size` / `rx` / `ry` / `strokeWidth`: `[0, 1]`, a fraction of the half-size.
- `angle` / `curvature`: the channel's own units. Each part has its own scale, so two parts can take opposite ranges.
- `{ field: "f", frame: [lo, hi] }` maps the field's schema domain onto that slice of the box. The domain stays on the schema.
- A categorical field spreads its categories evenly over `[lo, hi]`, and an edit snaps to the nearest one.
- `{ fn: (d) => …, frame: true }` is derived in local units. Use it to place a part where another part's value puts it, such as a forearm at the end of an upper arm.

`x` / `y` / `size` describe the box, so they stay off the parts. A part that states no position sits at the centre. `{ value }` is in pixels, so use `frame:` for anything that should scale with the glyph.

<Section id="why-scales" title="Why they're real scales">

A `frame:` channel is a real scale, built once per row, so the ordinary edits work inside a box. `move`, `slide`, `rotate` and `resize` invert a gesture through the same mapping that placed the part, and `.accepts()` reports the field's real range to an [external control](/editing/external-controls).

The chart's axes ignore `frame:` channels. An eye at `{ frame: -0.4 }` leaves the x domain and the axes unchanged.

</Section>

<Section id="scaling" title="Everything scales together">

A part's geometry is a fraction of the box, so resizing the glyph resizes its contents. An edit on an inner part still writes its own field on its own domain.

An edit on the composite's own `x` / `y` / `size` moves or resizes the whole glyph. The box covers the glyph, so you can grab it anywhere, including between the parts. A part with its own edit takes the drag first.

<Section id="parts" title="What box mode returns">

Box mode returns the box first, then the parts, all as plain marks. The box carries the composite's `x` / `y` / `size`, so those fields still build the chart's axes. Without an edit on them, the box is inert.

Two limits apply to a part placed in the box:

- A `{ fn }` channel is called once per row, as `(d, 0, [d])`, so it sees only its own row. Read the field instead. Its result is in pixels; add `frame: true` to return local units.
- A line-family mark inside a box is built one row at a time, so it cannot join rows into a series, and it logs a warning. To connect rows, position it on the global scales, or move it out of the composite.

A part with no `frame:` channel keeps the global scales, so one part of a glyph can still span to a data value.

</Section>

<Section id="face" title="Build a face with one brow">

[`face()`](/marks/face) is a composite in box mode: a `point` head, two [`ellipse`](/marks/ellipse) eyes, two `tickY` brows and a [`curveY`](/marks/curve) mouth. It is a preset, so you can build a different face from the same parts. Here it has one brow instead of two.

The brow and the mouth are both [`curve`](/marks/curve) marks. `curvature` is the apex's offset from the chord, as a fraction of the half-chord, so it scales with the glyph. Positive curvature bows to the left of the curve's direction, which arches a rightward chord upward. A descending `frame:` range reverses that, so a rising `grump` dips the brow and a rising `mood` deepens the smile.
