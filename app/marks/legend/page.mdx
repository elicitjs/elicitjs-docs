# Legend

<Lead>A legend is a key for one **encoding**: a field on a non-positional channel such as `fill`, `size` or `symbol`. Declare it on the channel (`fill: { field, legend: true }`), or compose `legendColor()` / `legendSize()`. It reserves space on its side, so the plot shrinks and the legend never overlaps the marks. With an edit it becomes a picker: click a swatch to set a category, or drag a ramp handle to set a value.</Lead>

<ApiReference entries={api} />

<Section id="legends-key" title="The legends key">

An encoding is a (channel, field) pair. A scale belongs to an encoding, and a legend belongs to a scale.

There are three ways to ask for one, most specific first:

1. **an element you compose** — `legendColor({ field: "group" })`
2. **the channel** — `fill: { field: "group", legend: { anchor: "bottom" } }`
3. **the spec** — `legends: true`

Each wins over the ones below it. `legends: { fill: false }` suppresses a channel; `legend: false` on a channel suppresses that one encoding.

`legends` defaults to off, unlike `axes`. A legend reserves layout space, so adding one shrinks the plot.

Two marks stating the same encoding share one scale and get one legend. Two marks with different fields on one channel are two encodings. They get two scales and two keys, in different colour families.

</Section>

<Section id="discrete" title="A discrete colour legend">

`legendColor()` draws a swatch per category. Here it names no field: `fill` carries one encoding, so the legend binds to that scale. `anchor` sets which side it's on. The plot shrinks to leave room, so the legend never overlaps the marks.

The title defaults to the encoded field's name.

<Section id="size" title="A size legend">

`legendSize()` over a quantitative field draws graduated circles at tick values.

The radii come from the channel's scale. `size` defaults to a **linear radius**, so the same pointer movement makes the same change in value anywhere on the scale. Pass `scale: "sqrt"` on the channel for linear area instead, the convention for a static read. The legend follows either way.

```js
size: { field: "people", scale: "sqrt" }
```

<Example
  code={graduatedSize}
  title="Graduated circles"
  blurb="Nested circles at tick values, sized by the same scale as the dots."
/>

A categorical `size` field gets swatches instead — one dot per category, at that category's radius.

</Section>

<Section id="angle-width" title="Theta and stroke width">

Every legendable channel gets a key shaped like the channel. `theta` draws a fan of spokes at their encoded bearings. `strokeWidth` draws a stack of segments at their encoded thicknesses. Both read the scale, so the key matches the marks.

<Example
  code={angleAndWidth}
  title="A fan and a weight stack"
  blurb="One needle mark encoding two channels; a key for each."
/>

Legendable channels are `fill`, `stroke`, `size`, `symbol`, `opacity`, `theta`, `strokeWidth` and `strokeDash`. A legend on any other channel draws nothing and logs a warning. For `x` and `y`, the axis is the key. `angle`, a mark's rotation in place, has no key.

</Section>

<Section id="bottom" title="Any side">

`anchor: 'bottom'` (or `'top'`) lays the swatches out in a row and reserves space on that side. The row sits past the axis, clear of the x-axis labels.

<Section id="two-encodings" title="Two encodings on one channel">

A scale belongs to one encoding, so two marks colouring by different fields get two scales. Each has its own domain, colour family and key, and each legend takes its column from the channel.

<Example
  code={pinTheColumn}
  title="Two encodings on fill"
  blurb="Two scales, two keys, two colour families — and each picker writes its own column."
  try={(
    <>
      <b>Click</b> a swatch in either legend — each writes only its own column.
    </>
  )}
/>

When you compose a legend **by hand** for a channel that carries two encodings, say which with `field`:

```js
legendColor({ field: "goal" })
```

With one encoding on the channel, leave `field` out. With two and no `field`, the legend takes the first and logs a warning naming both.

In a multi-table schema, `table` names which table the column is in. A hand-composed legend needs it when the encoding doesn't settle the table.

</Section>

<Section id="declare-on-the-mark" title="Declaring it on the channel">

Putting `legend:` on the channel is the shortest way to a correct legend. The channel already names the field and the mark names the table, so the legend restates neither.

```js
fill: { field: "group", legend: true }
fill: { field: "group", legend: { anchor: "bottom", title: "region" } }
fill: { field: "group", legend: false }   // suppress under legends: true
```

A picker goes in the same place. The gesture happens on the legend, and the bars stay inert.

```js
fill: { field: "group", legend: { edit: edit.legend.category() } }
```

<Example
  code={declareOnTheMark}
  title="The picker on the fill channel"
  blurb="No legendColor() in the spec — the legend is built from the encoding."
  try={(
    <>
      <b>Click</b> a bar to select it, then <b>click</b> a swatch to change its group.
    </>
  )}
/>

Compose a `legendColor()` for the same encoding and it takes over that legend, edit included. The channel says what is edited, and the element sets how it looks:

```js
barY({ channels: { fill: { field: "group", legend: { edit: edit.legend.category() } } } }),
legendColor({ anchor: "bottom" }),
```

</Section>

<Section id="dynamic-target" title="Editing a selected item">

Selection is interface state, kept outside the data. Give the bars an `edit.select()` and a click selects one, drawing a highlight outline. The legend's `row` defaults to the selection, so the swatch you click edits the bar you picked. See [Selection](/editing/selection).

The swatch holding the target row's current value is ringed, so the legend shows what a click would replace. With nothing selected, a picker has no target and shows no ring. A one-row table is always the target.

Pin `row` to a number, an array of indices, or a `(data, { selection }) => index` function to override.

<Example
  code={pickAndEdit}
  title="Pick a bar, then edit its group"
  blurb="The bars carry edit.select(); the legend edits the selected bar. Nothing about selection touches the data."
  try={(
    <>
      <b>Click</b> a bar to select it, then <b>click</b> a legend swatch to change its group.
    </>
  )}
/>

</Section>

<Section id="multi-select" title="Editing several rows at once">

`edit.select({ multi: true })` makes shift-click (or meta-click) add a row to the selection. Shift-click a selected row to take it back out. A plain click still replaces the selection.

A picker writes every selected row, so one swatch click recategorises the whole selection. Where the selected rows hold different values, each of those swatches is ringed.

<Example
  code={multiSelectPicker}
  title="Shift-click to select several bars"
  blurb="One swatch click sets the group on every selected bar."
  try={(
    <>
      <b>Click</b> a bar, <b>shift-click</b> another, then <b>click</b> a swatch.
    </>
  )}
/>

From your page code, `el.select([0, 2])` replaces the selection with those rows, `el.toggleSelection(i)` adds or removes one, `el.selectAll()` takes every row, and `el.selectWhere('group', 'North', { all: true })` takes a whole category. `el.getSelectionAll()` reads them back.

</Section>

<Section id="categories" title="Editing the category list">

The pickers above write a row. `edit.scale.categories()` writes the **domain**: the list of categories on the scale the legend draws. It needs no target row.

Double-click a swatch to rename its category, click the × to drop it, and double-click the + to add one. Renaming relabels every row carrying the old value, and removing deletes those rows, so the schema and the data stay in step.

<Example
  code={editTheCategories}
  title="Rename, remove, add"
  blurb="The domain and the rows move together."
  try={(
    <>
      <b>Double-click</b> a swatch to rename · <b>click</b> a × to remove · <b>double-click</b> the ＋ to add.
    </>
  )}
/>

The same edit works on an axis — `axisX({ edit: edit.scale.categories() })` — because both draw a scale.

Where one scale spans several columns, the edit writes all of them, including columns in different tables. A rename applies to every column that shares the category.
