# Trend + Band

<Lead>`trend` elicits a **parametric line** from one row `{ intercept, slope }`, drawn as `y = intercept + slope·x` across the plot. An intercept handle at `anchor` (`x = 0` by default) moves the line up and down. A slope grip at each end rotates it about the anchor. `trendBand` draws the uncertainty around it: a range on the intercept, a range on the slope, and every line between them.</Lead>

<ApiReference entries={api} />

<Section id="axes" title="Its channels name the axes, not the columns">

A trend's `x` and `y` channels name the plot's **axes**, not columns of its row. Declare their domains in the schema. Domains that span both sides of zero put the intercept in the middle of the frame.

When `axes` is unset, a chart with a trend crosses its axes at the origin. Set `axes: { origin: true | false }` to state the frame yourself. `origin: false` gives the ordinary left/bottom frame. See [Axis, Grid & Rule](/marks/axes#global).

</Section>

<Section id="not-creatable" title="Trend can't be created by a gesture">

A trend line is **parametric**. Its position comes from `intercept` and `slope`, and a click has no `x`/`y` to invert into them, so a plane `create` can't add one. See the [create matrix](/editing/existence#what-can-create). Set a trend by editing its parameters.

</Section>

<Section id="inert" title="Inert until an edit names the column">

`trend()` with no edit draws the line without handles and writes nothing. Like every mark, it stays a view until an `edit` names the column a gesture sets: `edit.trend.intercept()` on the intercept channel, `edit.trend.slope()` on the slope channel. Set a stage on the edit, as elsewhere: `edit.trend.slope({ stage: 1 })`.

<Section id="twostep" title="Intercept, then slope">

Stage 0: drag the intercept handle to set the level. Stage 1: drag either end grip to set the slope, rotating the line about the anchor.

The parameters are channels. Rename a column with `channels: { slope: { field: "r" } }`, or pin it to a constant with `{ datum }`. They are unscaled: each stays in its own units and is projected through `x` and `y`.

`axes` moves only the axis spines. The handles follow `anchor` and `probe`. `anchor` is 0 when 0 lies in the x domain, and the domain's start otherwise. Over a domain starting at 0 or above, that puts the intercept handle on a left/bottom y-axis. Pair it with `grip: "probe"` for a single slope handle at the domain's far end. The default pair of grips would put one on top of the intercept handle.

<Section id="grip" title="Rotating the line">

The slope grips sit on the line’s ends. Dragging one passes the line through the pointer, so the line rotates a full turn: drag an end up and over the anchor, and the line swings past vertical and down the other side. Both ends carry the same edit, and each stays inside the plot at every angle.

A vertical line has no slope. The gesture holds while the pointer is in the anchor’s column, and `slope` grows without bound as you approach it. Bound it with a `clamp` on the column, as for any field.

`grip: "probe"` pins a single grip at `x = probe` instead, sliding vertically at that column. Reachable slope is then capped at `ySpan / (probe − anchor)`.

<Section id="band" title="The band around the line">

`trendBand` takes the same two parameters plus a **spread** on each: `interceptSpread` and `slopeSpread`, half-widths in the field’s own units. It draws every line those ranges allow. The envelope is exact: piecewise linear, with one kink where `x` crosses zero and only the intercept range is left.

The two marks are views of one dataset. Put a plane or probe edit on the band or on the line, not both, or it runs twice per gesture. The band's spread channels take `edit.trend.interceptSpread()` and `edit.trend.slopeSpread()`, shown below.

<Example
  code={aBandAroundTheLine}
  title="A band around the line"
  blurb="Every line whose intercept is within aSd and whose slope is within bSd."
/>

For an asymmetric band, name the ends instead: `intercept1`/`intercept2` and `slope1`/`slope2`, the same `1`/`2` spelling [`area`](/marks/area#band) and `rect` use. Where both forms are declared, the range form wins. Pair it with `ordering` to keep the ends in order.

<Section id="render" title="Three readings of one band">

`render` sets how the family is drawn. `region` (the default) is one polygon: the exact envelope. `gradient` stacks `levels` nested envelopes, so the ink darkens toward the line. `samples` draws individual lines from the family. Its `distribution` is `normal` (the bounds are a `sigma`-wide envelope, so about 95% of draws land inside) or `uniform` (every line in the range equally likely).

The filled forms use `fillOpacity` (default `0.18`). `samples` uses `strokeOpacity` (default `0.15`) for each line, so the fan gets denser as you raise `samples`. Lower `strokeOpacity` to thin it out.

<Section id="correlation" title="A correlation is a pinned trend">

To elicit a correlation, pin the intercept at the origin and limit the slope to `[-1, 1]`. Pin with a constant channel, `intercept: { datum: 0 }`, which names no column, so no edit writes it. Limit with a `clamp`.

Stage 0 aims the line. Under [`probe`](/editing/probe) the line follows the pointer's `x`, and a click sets it and advances. Stage 1 opens the band: `slopeSpread` is how far the line through the pointer tilts from the committed one, so the fan's edge sits under the cursor.

Both axes span `[-1, 1]` over a square plot, so the line's screen angle reads as `r`. This interface ships as [`widgets.lineCone`](/widgets#linecone).
