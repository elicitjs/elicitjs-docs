# Bar

<Lead>`bar` draws one rectangle per row: a categorical **band** on one axis, and a **value** on the other, drawn as length from a baseline or as a span (`x1`/`x2`, `y1`/`y2`). `bar` takes its orientation from the band axis; `barY` forces vertical, `barX` horizontal. For rectangles that span both axes, use [`rect`](/marks/rect) with `brushRect()`.</Lead>

`gradient: { stops, direction }` fills each bar with a linear gradient over its own box. Each stop is `[offset, colour]`, from 0 to 1. `direction: 'vertical'` (the default) runs from the bottom of the bar to its top; `'horizontal'` runs left to right. `area` and `rect` take the same option.

<Section id="stack" title="Stacked bars">

The `stack` channel stacks the bars that share a band. Each segment sits on the cumulative total of the ones before it. Rows with the same `x` (or `y`, for `barX`) stack together. Declare a schema domain that covers the stacked **total**.

The `stack` field names each segment, and must be categorical or ordinal. Segments follow the order of its schema domain, so the same category sits at the same height in every band. With no domain declared, they follow the order the values first appear in the data. Colour is separate: bind `fill` to the same field to colour each segment by its category.

`stack` is the counterpart of `xOffset`: `xOffset` places the rows of a band side by side, and `stack` places them end to end. Without either, rows that share a band draw over each other. Elicit.js logs a warning, unless the bars are translucent (a constant `opacity` or `fillOpacity` below 1), which layers them on purpose. A span (`x1`/`x2` or `y1`/`y2`) places each bar itself, so `stack` has no effect on it.

<Example
  code={aStackedBarChart}
  title="A stacked bar chart"
  blurb={'stack and fill both on { field: "asset" }. The pct domain covers the total, [0, 100].'}
/>

</Section>

<Section id="grouped" title="Grouped bars (xOffset, yOffset)">

`xOffset` splits each `x` category into one sub-band per value of a second field, so the bars of one category sit side by side. `yOffset` does the same inside each `y` category, for grouped `barX`. The offset needs a categorical `x` (or `y`) to divide. It has no axis, so colour the groups with `fill` on the same field and turn on its legend.

Sub-bands touch by default, and the gap between categories is the `x` band's padding. `scale: { padding }` on the offset channel opens a gap inside each group. `yOffset` puts its first value at the bottom of the slot, as a band `y` axis does.

<Example
  code={groupedBars}
  title="Grouped bars"
  blurb={'xOffset: { field: "year" } splits each region into three sub-bands. y carries edit: move().'}
  try={<><b>Drag</b> any bar up or down.</>}
/>

A bar draws only for a row that names both a category and a group. Combine `xOffset` with `stack` and each sub-band stacks on its own. `create()` and `toggle()` read the group from where you click, and `move({ channels: ["x", "xOffset"] })` drags a bar into another category and group.

<Section id="slice" title="Slicing a stack">

A stacked bar divides one total among its rows. Three gestures reshape it, the same three that work on a [pie or donut](/marks/arc#slice):

- `edit.stack.cut()` — **click** inside a segment to divide it in two at that point.
- `edit.stack.edge()` — **drag** a boundary to move value across it. Only the two segments it separates change.
- `edit.stack.merge()` — **double-click** a boundary to fuse those two back into one.

All three preserve the band's total. Cutting divides a magnitude, dragging moves value from one row to its neighbour, and merging adds two into one. Boundary handles appear once one of these edits is set, and take the shared `handles` / `handleSize` / `handleColor` options.

A cut mints a row and writes its category into the `stack` field, taking a value from that field's schema domain, so building a stack takes no typing. The new segment takes a category that sorts next to the one you cut, so the other segments keep their places. A **closed** domain (the default) hands out the values that band doesn't yet use, and refuses the cut once they run out. Each band draws from its own copy of the domain, so `bonds` in 2023 and `bonds` in 2024 are both available.

<Example
  code={cutAStackIntoParts}
  title="Cut a stack into parts"
  blurb="Each year starts as one 100% block. The asset domain declares four categories, so each band takes four cuts."
  try={<><b>Click</b> inside a segment to cut it, <b>drag</b> a boundary to shift value, <b>double-click</b> one to merge.</>}
/>

Set `open: true` on the field's schema entry and the domain becomes a starting set instead: a cut appends a new category to it, named from `label` (`"Category"` by default) for you to rename later with `edit.scale.categories()`. An open field also skips the out-of-domain check on seed data.

<Example
  code={anOpenDomain}
  title="An open domain"
  blurb={'holding is declared open, so each cut adds a category rather than running out. label: "Holding" names them.'}
  try={<><b>Click</b> inside a segment to add a holding.</>}
/>

</Section>

<Section id="span" title="Explicit spans (x1/x2, y1/y2)">

Give the value axis two endpoints, `x1`/`x2` for `barX` or `y1`/`y2` for `barY`, and each bar spans from one to the other instead of starting at the baseline. Use it for a range per category, as in a Gantt chart. `x1`/`x2` share the scale of `x` (likewise `y1`/`y2` with `y`), so only one needs an explicit type and domain.

<Section id="editing" title="Editing bars">

Put `edit: move()` on the value channel and drag a bar to rewrite its value. With `pick: "nearest"`, you grab a bar from anywhere in its column, which helps with thin bars. A bar dragged to the baseline collapses to zero length but keeps a minimum grab target, with either pick mode, so you can drag it back up.
