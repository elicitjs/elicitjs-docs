# Network

<Lead>A **network** is two tables, nodes and the links between them, declared with `structure: "network"`. `node()` draws a labelled dot, and `link()` draws one connector per link row, with arrowheads when directed; a `ports` channel marks where links can meet a node. `edit.network.connect`, `rewire` and `reverse` build the topology, and `create`, `move`, `editText` and `remove` work as on any other mark.</Lead>

<ApiReference entries={api} />

<Section id="schema" title="Declaring the structure">

`structure: "network"` gives the dataset two tables in the roles `nodes` and `links`. The default, `"table"`, is a single table declared as a bare field map.

```js
schema: {
  structure: "network",
  tables: {
    nodes: {
      id: { type: "categorical", key: true, open: true },
      label: { type: "categorical", open: true },
      x: { type: "quantitative", domain: [0, 100] },
      y: { type: "quantitative", domain: [0, 100] },
    },
    links: {
      source: { type: "ref" },
      target: { type: "ref" },
      weight: { type: "quantitative", domain: [0, 1] },
    },
  },
}
```

`key: true` marks the column that identifies a node. `type: "ref"` marks a column that names one; its domain is the key column's values. Pair `key` with `open: true` so a gesture that mints a node can give it a new identity.

`data` is keyed by table name. A table you leave out starts empty.

```js
data: {
  nodes: [{ id: "a", label: "Ana", x: 20, y: 70 }],
  links: [],
}
```

`getData()`, `onChange` and `setData` use the same shape.

<Section id="directed" title="Kinds of network">

Three flags on the links table say what its pairs mean. Declare them on the long form:

```js
tables: {
  nodes: { fields: { … } },
  links: {
    directed: true,
    multi: true,
    selfLoops: true,
    fields: { source: { type: "ref" }, target: { type: "ref" } },
  },
}
```

`directed` and `multi` together give the four usual kinds of network:

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th>kind</th><th><code>directed</code></th><th><code>multi</code></th><th>one pair may have</th></tr>
    </thead>
    <tbody>
      <tr><td>graph</td><td><code>false</code></td><td>—</td><td>one link</td></tr>
      <tr><td>digraph</td><td><code>true</code></td><td>—</td><td>one link each way</td></tr>
      <tr><td>multigraph</td><td><code>false</code></td><td><code>true</code></td><td>any number of links</td></tr>
      <tr><td>multidigraph</td><td><code>true</code></td><td><code>true</code></td><td>any number, either way</td></tr>
    </tbody>
  </table>
</div>

`selfLoops: true` adds links from a node to itself to any of the four. See [Parallel links and loops](#multi).

- `directed: true` draws an arrowhead at the target and bows reciprocal links apart, so `a → b` and `b → a` stay readable. It also enables `edit.network.reverse`.
- `directed: false` treats a pair as unordered: `b → a` is the same link as `a → b`.
- With `directed` left out, links draw without arrowheads, and `a → b` and `b → a` are two different links.

<Section id="multi" title="Parallel links and loops">

`multi: true` lets `connect` and `rewire` add a link between two nodes that already share one. Links between the same two nodes fan apart (`curvature: "auto"`).

`selfLoops: true` lets them link a node to itself. Drag from a port to another port of the same node, or move off the port and release on the node's body.

A link from a node to itself draws as a loop. It leaves and returns by one edge, or goes round the node from an `out` port to an `in` port. More loops on the same node take the free edges first, then nest outward. `loopRadius` sets how far a loop reaches (default `22`).

Rows holding a parallel pair or a loop always draw. With `multi: false` or `selfLoops: false`, they also log a warning.

<Section id="naming" title="Naming the tables">

Name the tables for your data, and give each a `role`:

```js
tables: {
  claims:   { role: "nodes", fields: { … } },
  supports: { role: "links", fields: { … } },
}
```

`data` and `getData()` are then keyed `claims` and `supports`. Marks and edits find their table by role, so `link()` draws `supports` by default. The [argument map](#draw) below uses these names.

</Section>

<Section id="draw" title="Drawing a network">

`node()` draws a dot with a label above it. It takes `x` and `y` once for both, and draws the label from a `text` channel. It is a preset over `composite` and works on any table. Any other mark can draw the nodes too; see [What can be a node](#node-marks).

`link()` draws the links table. Each end sits at the node its `ref` column names.

<Section id="curves" title="Connector styles">

`curve` sets a link's shape:

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th><code>curve</code></th><th>shape</th></tr>
    </thead>
    <tbody>
      <tr><td><code>"line"</code></td><td>straight segment (the default)</td></tr>
      <tr><td><code>"step"</code></td><td>right-angled elbow, turning midway</td></tr>
      <tr><td><code>"stepBefore"</code> / <code>"stepAfter"</code></td><td>elbow turning at the source / at the target</td></tr>
      <tr><td><code>"orthogonal"</code></td><td>elbow that leaves each node square out of one of its edges</td></tr>
      <tr><td><code>"arc"</code></td><td>quadratic bow to one side</td></tr>
      <tr><td><code>"bezier"</code></td><td>cubic with square tangents; <code>"smooth"</code> is an alias</td></tr>
    </tbody>
  </table>
</div>

The `"step"` kinds turn on the straight line between two node positions. `"orthogonal"` leaves and arrives perpendicular to an edge of the node's shape; see [Where a link meets a node](#routing). `cornerRadius` rounds its turns (default `8`; `0` is square).

Give `curve` a column to mix shapes in one mark:

```js
link({ channels: { curve: { field: "kind" } } })
```

Any column works, or `{ fn: d => … }` to map one. `arrow` reads a column the same way, so one field can drive both shape and arrowheads.

`curvature` sets how far a link bows. The default, `"auto"`, fans out links that share a pair of nodes and keeps a lone link straight. On a directed network every link bows to the same side of its direction, so `a → b` and `b → a` separate. Pass a number to bow every link equally, and `spread` to change the gap `"auto"` leaves between siblings.

Under `"auto"`, a lone `"arc"` draws straight. A `"line"` with curvature draws as an arc, so links sharing a pair fan apart on a plain `link()`.

A link whose source and target are the same node draws a loop; see [Parallel links and loops](#multi).

A `click` edit such as `reverse` or `remove` responds anywhere along the line.

<Section id="routing" title="Where a link meets a node">

A link meets the shape the node mark draws: a dot's circle, a rect's edges, a sticker's paper. With no node mark, it ends at each node's position.

How an end meets the shape depends on whether the node has [ports](#ports):

- **With ports**, an end connects to a port. A pinned end uses the port on its side. An unpinned end uses the usable port facing the other node, and switches ports when the nodes pass each other.
- **Without ports**, an unpinned end slides. It sits where the line between the two centres leaves the shape, and moves smoothly as the nodes move. A pinned end sits at the middle of its edge.

`inset` sets how far from a node's shape a link stops, in px (default `0`). `sourceInset` and `targetInset` set each end. An end at a port touches the port. An arrowhead fits in the gap.

An `"orthogonal"` connector leaves each end square to its edge and joins the two with the fewest turns. Two sliding ends nearly in line join with one straight leg; further apart, they join with a Z. It routes around a node in the way. Overlapping nodes get the plain route. `"line"` and `"bezier"` connectors also meet the shape, and a bezier leaves a pinned edge square-on.

`sourceOffset` and `targetOffset` move a pinned end along its edge, as a fraction from `-0.4` to `0.4`. Positive runs clockwise: right along the top, down the right, left along the bottom, up the left.

<Section id="ports" title="Ports">

A **port** is a dot on a node's edge where a link starts or ends. Declare ports with a `ports` channel on the mark that draws the nodes (any mark in [What can be a node](#node-marks)), and put `edit.network.connect()` on it:

```js
sticker({
  channels: {
    x: { field: "x", edit: move({ channels: ["x", "y"], mode: "relative" }) },
    y: { field: "y" },
    text: { field: "label" },
    ports: {
      value: { out: ["right"], in: ["left"] },
      edit: edit.network.connect(),
    },
  },
})
```

The value sets which edges a link may use. Use `fn` or `field` instead of `value` to vary it per node.

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th><code>value</code></th><th>ports</th></tr>
    </thead>
    <tbody>
      <tr><td><code>true</code></td><td>all four edges, either way</td></tr>
      <tr><td><code>"right"</code> or <code>["left", "right"]</code></td><td>those edges, either way</td></tr>
      <tr><td><code>{"{ out: [\"right\"], in: [\"left\"] }"}</code></td><td>links leave by the right and arrive by the left (directed networks)</td></tr>
      <tr><td><code>false</code></td><td>none</td></tr>
    </tbody>
  </table>
</div>

Hover a node to see the ports a link can leave by. Start a drag and the ports that accept it light up. Both follow the `out` and `in` edges and the dataset's constraints.

Drag from a port and a dashed connector follows the pointer. Release on a port to connect there, or on a node's body to connect at its facing port. Release on empty space to cancel. Drag the body to move the node.

<Section id="recording" title="Recording sides">

To record which edge each end uses, name the columns in `sourceSide` and `targetSide` channels on the `link` mark. Declare them in the links table as `categorical` over `"top"`, `"right"`, `"bottom"` and `"left"`:

```js
link({
  channels: {
    sourceSide: { field: "fromSide" },
    targetSide: { field: "toSide" },
  },
})
```

The gestures write those columns, and write `source` and `target` to the links table's `ref` columns:

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th>gesture</th><th>the links table</th></tr>
    </thead>
    <tbody>
      <tr><td>port to port</td><td>a new row, with both sides</td></tr>
      <tr><td>port to a node&rsquo;s body</td><td>a new row; the target side is <code>null</code></td></tr>
      <tr><td>a link&rsquo;s end to another node</td><td>that row re-pointed, with its new side</td></tr>
      <tr><td>a link&rsquo;s end to empty space</td><td>that row removed</td></tr>
    </tbody>
  </table>
</div>

A `null` side is unpinned. It meets the facing port, or slides along a node that has no ports. With no side channel or [side option](#sides), every end is unpinned.

`edit.network.rewire()` in the `link` mark's `edits` puts a handle on each end while you hover the connector. Drag one to another node to reconnect it, or into empty space to disconnect it. `rewire({ channels: ["target"] })` handles one end only.

<Section id="sides" title="Pinned sides">

As options, `sourceSide` and `targetSide` pin every link's ends to `"top"`, `"right"`, `"bottom"` or `"left"`, so a diagram reads the same way however the boxes are arranged. Both default to `null`. A pinned end leaves its edge square-on, and routes around its own box if the other node is behind it.

The options set how links draw and write nothing to the data. Give one `{ fn: d => … }` to derive a side from a column you already have. To record sides in the data, use channels; see [Recording sides](#recording).

<Section id="node-marks" title="What can be a node">

Any mark that draws a shape at an `x` and a `y` can draw the nodes: `point`, `rect`, `text`, a `composite`, and the rest. Point it at the nodes table; channels, scales and edits work as usual. See [Which table a mark draws](/schema#table).

Links meet the shape the mark draws, and a [`ports`](#ports) channel puts ports on that shape's edges:

<Section id="gestures" title="Building the topology">

Three edits are specific to networks. The rest is ordinary editing.

`edit.network.connect()` creates a link. Put it on a [`ports`](#ports) channel, or in the node mark's `edits` to drag from a node's body. On the body, separate it from `move` with `when`: `connect({ when: when.shift })` beside `move({ when: when.noShift })`. With `selfLoops: true`, release on the starting node to draw a loop. When the nodes draw no shape, a drop within `threshold` px of a node's centre connects.

`edit.network.rewire()` moves a link's ends; see [Recording sides](#recording).

`edit.network.reverse()` on the `link` mark swaps the two ends on a click and keeps every other column. Give it a `when` if the mark carries another click edit. On `directed: false` it leaves the row unchanged and logs a warning.

`create()` mints a node where you click. The node table's `key` gives it an identity, so you can link it straight away.

`remove()` deletes a node and every link to it.

<Section id="attributes" title="Link attributes">

A link row is a row like any other. Give the links table columns, then encode them on `link()`'s style channels or edit them with `set`, `cycle` and `editText`.

`channels.text` draws a label at the midpoint, and takes `editText()` as a `text` mark does. Double-click anywhere along the connector to open the editor.

`stroke` and `strokeWidth` paint the connector and its arrowhead. `fill` paints the label (default: the theme's ink).

A label sits on its connector. `labelBackground` puts a plate behind it:

```js
link({ labelBackground: true, channels: { text: { field: "note" } } })
```

`true` uses the theme's backdrop, which reads as a gap in the line. Pass a colour string for any other plate. `labelOpacity` (default `0.9`) sets how much of the connector shows through. `labelPadding` and `labelRadius` size the plate.
