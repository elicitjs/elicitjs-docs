# Network

<Lead>A **network** is two tables — nodes and the links between them — declared with `structure: "network"`. `node()` draws a labelled dot; `link()` draws one connector per link row, straight or curved, with arrowheads when directed. `edit.network.connect`, `rewire` and `reverse` build the topology; `create`, `move`, `editText` and `remove` work as on any other mark.</Lead>

<ApiReference entries={api} />

<Section id="schema" title="Declaring the structure">

`structure: "network"` gives the dataset two tables in the roles `nodes` and `links`. The default `"table"` is one table — a bare field map, as on every other chart here.

```js
schema: {
  structure: "network",
  tables: {
    nodes: {
      id: { type: "categorical", key: true, open: true },
      label: { type: "categorical", open: true },
      x: { type: "quantitative", domain: [0, 100] },
      y: { type: "quantitative", domain: [0, 100] },
    },
    links: {
      source: { type: "ref" },
      target: { type: "ref" },
      weight: { type: "quantitative", domain: [0, 1] },
    },
  },
}
```

`key: true` marks the column that identifies a node. `type: "ref"` marks a column that names one; its domain comes from the key, so you never list node ids twice.

Pair `key` with `open: true` so a gesture that mints a node can take a fresh identity.

`data` is keyed by table name. Omit a table and it starts empty — a diagram built entirely by gesture needs no `data` at all.

```js
data: {
  nodes: [{ id: "a", label: "Ana", x: 20, y: 70 }],
  links: [],
}
```

`getData()`, `onChange` and `setData` use the same shape.

<Section id="directed" title="Directed or undirected">

`directed` on the links table says whether `source` → `target` is ordered. Declare it on the long form:

```js
tables: {
  nodes: { fields: { … } },
  links: {
    directed: true,
    fields: { source: { type: "ref" }, target: { type: "ref" } },
  },
}
```

`directed: true` draws an arrowhead at the target, bows reciprocal links apart so `a → b` and `b → a` stay readable, and enables `edit.network.reverse`.

`directed: false` treats the pair as unordered: `edit.network.connect` refuses `b → a` once `a → b` exists.

Leave it out for no arrowheads, and `connect` rejects only the exact pair you already have.

<Section id="naming" title="Naming the tables">

Name the tables for your data. Give each a `role`:

```js
tables: {
  claims:   { role: "nodes", fields: { … } },
  supports: { role: "links", fields: { … } },
}
```

`data` and `getData()` are then keyed `claims` and `supports`. Marks and edits find their table by role, so `link()` still draws `supports` with no `table` option. The [argument map](#draw) below is written that way.

</Section>

<Section id="draw" title="Drawing a network">

A node is an ordinary mark — `point`, `rect`, `text`, or a `composite` over the node table. Every channel, scale and edit works as usual: a mark with no `table` draws the primary table, which for a network is the nodes. See [which table a mark draws](/schema#table) to point one at the links instead.

`node()` is the shorthand: a dot with a label above it. It states `x` and `y` once and shares them, and draws a label only when you give it a `text` channel. It is a preset over `composite`, not a network mark — point it at any table.

`link()` draws the link table. It reads endpoints from the node rows via the schema's `key` and `ref` columns, so it needs no endpoint configuration.

`inset` pulls both ends in so the line stops short of the node marks.

<Section id="curves" title="Connector styles">

`curve` sets a link's shape:

<div className="api-table-wrap">
  <table className="api-table">
    <thead>
      <tr><th><code>curve</code></th><th>shape</th></tr>
    </thead>
    <tbody>
      <tr><td><code>"line"</code></td><td>straight segment (the default)</td></tr>
      <tr><td><code>"step"</code></td><td>right-angled elbow, turning midway</td></tr>
      <tr><td><code>"stepBefore"</code> / <code>"stepAfter"</code></td><td>elbow turning at one end instead</td></tr>
      <tr><td><code>"orthogonal"</code></td><td>elbow that leaves each node square out of one of its edges</td></tr>
      <tr><td><code>"arc"</code></td><td>quadratic bow to one side</td></tr>
      <tr><td><code>"bezier"</code></td><td>cubic with square tangents; <code>"smooth"</code> is an alias</td></tr>
    </tbody>
  </table>
</div>

The `"step"` kinds turn on the straight line between two node positions, so a connector meets a box wherever that line happens to cross it. `"orthogonal"` docks to the box instead. It leaves and arrives perpendicular to an edge, and picks which edges from where the two nodes sit — left and right when they are side by side, top and bottom when they are stacked. `cornerRadius` rounds the turns.

`nodeWidth` and `nodeHeight` tell it how big a node is, in px. They read the node rows, so a constant sizes every node, a column sizes each one, and `{ fn: d => … }` derives it. A [sticker](/marks/sticker) measures its box from its own text, and `noteBox` measures it the same way:

```js
link({
  curve: "orthogonal",
  cornerRadius: 8,
  channels: {
    nodeWidth: { fn: (d) => noteBox(d.label, { maxWidth: 130 }).width },
    nodeHeight: { fn: (d) => noteBox(d.label, { maxWidth: 130 }).height },
  },
})
```

Pass `noteBox` the same sizing options you gave the sticker — it measures text, it does not read the mark. With neither channel set the connector docks to a small square around the node's position, so it still leaves square-on.

Give `curve` a column to mix them in one mark:

```js
link({ channels: { curve: { field: "kind" } } })
```

Any column works, or `{ fn: d => … }` to map one. `arrow` reads a column the same way, so one field can drive both shape and arrowheads.

`curvature` sets how far a link bows; default `"auto"` fans links that share a pair of nodes and keeps a lone link straight. On a directed network every link bows to the same side of its travel, so `a → b` and `b → a` separate. Pass a number to bow every link equally, and `spread` to change the gap `"auto"` leaves between siblings.

An `"arc"` at curvature `0` is a straight chord, so under `"auto"` a lone arc draws flat. A `"line"` with a bow is drawn as an arc — a straight segment cannot bend, so curvature wins over the named shape. That is why `"auto"` is visible on a plain `link()` that names no curve.

A link whose source and target are the same node draws a loop, whatever `curve` says. `loopRadius` sets how far it reaches; `edit.network.connect({ selfLoops: true })` lets you draw one.

`link()` is pickable along its whole length, so a `click` edit like `reverse` or `remove` lands anywhere on the line.

<Section id="sides" title="Pinned sides">

`sourceSide` and `targetSide` pin an end to `"top"`, `"right"`, `"bottom"` or `"left"` instead of choosing one, so a diagram reads the same way however the boxes are arranged. Both default to `"auto"`.

They are drawing options rather than data. Give one a `{ fn: d => … }` to derive a side from a column you already have — the flow's own `kind`, say — and nothing new is written to the dataset.

<Section id="gestures" title="Building the topology">

Only three gestures are network-specific; the rest is ordinary editing.

`edit.network.connect()` goes on the **node** mark: drag from one node and release on another to create a link. A ghost connector follows the pointer; release off a reachable node creates nothing.

Pair it with `when` if the node mark also carries a plain drag — otherwise both fire, `move` pulls the source under the pointer, and the release lands back where it started. `connect({ when: when.shift })` beside `move({ when: when.noShift })` is the usual split.

Release on the node you started from creates nothing, unless `selfLoops: true` — then you get a loop.

`edit.network.rewire()` on a `link` mark's `source` or `target` channel turns that end into a handle. Drag it onto another node to re-point the link. Both ends can carry one at once.

`edit.network.reverse()` on the `link` mark swaps the two ends on a click, keeping every other column. Give it a `when` if the mark carries another click edit. On `directed: false` it does nothing and logs a warning.

`create()` mints a node where you click — the plain creation edit. The node table's `key` gives the new row an identity, so you can link it straight away. Name it separately with `editText()` on the `text` channel.

`remove()` deletes a node and takes its links with it. A `ref` must name a node that exists, so links to a removed node are dropped from the dataset, not just hidden.

<Section id="attributes" title="Link attributes">

A link row is a row like any other. Give the link table columns and encode them on `link()`'s style channels, or edit them with `set`, `cycle` and `editText`.

`channels.text` draws a label at the midpoint and takes `editText()` the same way a `text` mark does. Double-click anywhere along the connector to open the editor.

`stroke` and `strokeWidth` paint the connector and its arrowhead. `fill` paints the label (default: the theme's ink). Stroke never reaches the label, so a thick line does not outline the text.

A label sits on its connector, so the line runs through it. `labelBackground` puts a plate underneath:

```js
link({ labelBackground: true, channels: { text: { field: "note" } } })
```

`true` uses the theme's backdrop, which reads as a gap in the line; pass a colour string for anything else. `labelOpacity` (default `0.9`) sets how much of the connector shows through; `labelPadding` and `labelRadius` size the plate.
