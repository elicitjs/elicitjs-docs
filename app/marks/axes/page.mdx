# Axis, Grid & Rule

<Lead>Axes and gridlines are **chart elements** — they draw a scale rather than the data. Prefer <code className="inline">{"elicit.elements.*"}</code> (or <code className="inline">ElicitSpec.elements</code>); the same factories stay aliased on <code className="inline">{"plot.*"}</code>. Configure them via the global <code className="inline">{"axes: {…}"}</code> convenience, or compose <code className="inline">elements.axisX</code> / <code className="inline">gridY</code> explicitly. <code className="inline">ruleY</code> is still a data mark.</Lead>

<Section id="chart-elements" title="Chart elements are not data marks">

`axis`, `grid`, `legend` and `axisRadial` are public as `elicit.elements.*`. They still work inside `marks` and on `plot.*`, and you can separate them with `elements: […]` on the spec (concatenated into the feature list). See [Mark & element contracts](/concepts/contracts).

A data mark views the dataset's columns through a `channels` map. A chart element views **one scale**, named by a singular `channel` (`'x'`, `'fill'`, `'angle'`), so it has no data-mark channel map and no fields of its own. (`axisRadial` may carry optional x/y **placement** channels for per-row rings — placement chrome, not elicitation encoding.)

Its `stroke`, `fill` and `fontSize` paint a spine and its labels rather than a datum, so they stay plain options instead of becoming channels.

An edit on a data mark writes a **row**; an edit on a chart element writes the **domain** (`edit.axis.*`). `create` therefore doesn't apply to an element — there is no row to mint. Since an element has no channel map, an edit on one recovers its field from the scale, which is how a legend picker knows what to write.

A legend also **reserves space**, shrinking the plot; nothing else does.

Both halves have an implicit layer on the spec: `axes` for the positional scales, [`legends`](/marks/legend#legends-key) for the rest.

</Section>

<Section id="global" title={"The global axes:{} convenience"}>

Pass a per-channel config to shape ticks, formats and titles, or a transform to reposition an axis. `axes: false` drops them entirely.

`origin: true` is the shorthand for crossing both axes at zero — declare it once instead of writing a `transform` on each channel by hand. It's the same frame [`trend`/`trendBand`](/marks/trend) draw automatically; `origin: false` states the ordinary left/bottom frame explicitly on a chart that would otherwise infer the origin frame from its marks. A per-channel `transform` still covers anything `origin` doesn't — crossing at a value other than zero, or on one axis only.
