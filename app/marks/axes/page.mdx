# Axis, Grid & Rule

<Lead>Axes and gridlines are **chart elements** — they draw a scale rather than the data. Prefer <code className="inline">{"elicit.elements.*"}</code> (or <code className="inline">ElicitSpec.elements</code>); the same factories stay aliased on <code className="inline">{"plot.*"}</code>. Configure them via the global <code className="inline">{"axes: {…}"}</code> convenience, or compose <code className="inline">elements.axisX</code> / <code className="inline">gridY</code> explicitly. <code className="inline">ruleY</code> is still a data mark.</Lead>

<ApiReference entries={api} />

<Section id="chart-elements" title="Chart elements are not data marks">

`axis`, `grid`, `legend` and `axisRadial` are public as `elicit.elements.*`. They still work inside `marks` and on `plot.*`, and you can separate them with `elements: […]` on the spec (concatenated into the feature list). See [Mark & element contracts](/concepts/contracts).

A data mark views the dataset's columns through a `channels` map. A chart element views **one scale**, named by a singular `channel` (`'x'`, `'fill'`, `'angle'`), so it has no data-mark channel map and no fields of its own. (`axisRadial` may carry optional x/y **placement** channels for per-row rings — placement chrome, not elicitation encoding.)

Its `stroke`, `fill` and `fontSize` paint a spine and its labels rather than a datum, so they stay plain options instead of becoming channels.

An edit on a data mark writes a **row**; an edit on a chart element writes the **domain** (`edit.axis.*`). `create` therefore doesn't apply to an element — there is no row to mint. Since an element has no channel map, an edit on one recovers its field from the scale, which is how a legend picker knows what to write.

A legend also **reserves space**, shrinking the plot; nothing else does.

Both halves have an implicit layer on the spec: `axes` for the positional scales, [`legends`](/marks/legend#legends-key) for the rest.

</Section>

<Section id="global" title={"The global axes:{} convenience"}>

Pass a per-channel config to shape ticks, formats and titles, or a transform to reposition an axis. `axes: false` drops them entirely.

<Example
  code={gridlinesTicksFormatTitle}
  title="Gridlines, ticks, format & title"
  blurb="y gets a grid and percent formatting; x a tick count and a title."

`origin: true` is the shorthand for crossing both axes at zero — declare it once instead of writing a `transform` on each channel by hand. It's the same frame [`trend`/`trendBand`](/marks/trend) draw automatically; `origin: false` states the ordinary left/bottom frame explicitly on a chart that would otherwise infer the origin frame from its marks. A per-channel `transform` still covers anything `origin` doesn't — crossing at a value other than zero, or on one axis only.

<Section id="titles" title="Axis titles and band order">

`title` labels an axis. An x title sits centred below the tick labels. A y title runs along the axis, reading bottom to top on the left, and sits past the widest tick label, so it never crosses one. Leave room for it in `margins`.

A band or point y axis lists `domain[0]` at the bottom, the same direction a value increases. Set `scale: { reverse: true }` on the channel to list the categories top-down, as Vega-Lite and Observable Plot do for a horizontal bar chart.

<Example
  code={titlesAlongTheAxis}
  title="Titles along the axis"
  blurb={"axes: { x: { title }, y: { title } }; scale: { reverse: true } on the band y lists Sleep first."}
  try={(
    <>
      <b>Drag</b> a bar to change its hours.
    </>
  )}
/>

`titleAngle` sets the title's rotation in degrees. `titleAngle: 0` lays a y title flat, for a short unit label.

<Example
  code={aFlatYTitle}
  title="A flat y title"
  blurb={"axes: { y: { title: \"°C\", titleAngle: 0 } }"}
/>

</Section>

<Section id="styling" title="Styling an axis">

Every axis option below defaults to the [theme's](/theming#chrome) `axis` token of the same name, so set it once in a theme or here on one axis. `line: false` drops the spine and `tickSize: 0` the ticks. `tickPadding` sets the gap from tick to label, and `offset` moves the whole axis away from the plot. `labelAngle` turns the tick labels, and the axis reserves the room they need. A `\n` in a formatted label starts a second line.

<Example
  code={rotatedAndTwoLineLabels}
  title="Turned labels"
  blurb={"axes: { x: { labelAngle: 40, tickSize: 0 }, y: { grid: { strokeDash: \"2 3\" } } }"}
  try={"drag a bar."}
/>

`tickSize`, `stroke`, `fill` and `fontWeight` also take a function of the tick's value and index, and so do a grid's `stroke`, `strokeWidth` and `strokeDash`. Use it to mark a period boundary.

<Example
  code={conditionalTicks}
  title="Per-tick styling"
  blurb="Long ticks, bold two-line labels and solid gridlines on each January."
  try={"drag a point on the line."}
/>

`labelAlign` sets a label's text-anchor and `labelOffset` moves every label along the axis. A negative `tickPadding` with `labelAlign: "start"` puts a y axis's labels inside the plot, and a grid's `bandPosition: 0` draws its lines between the categories. `titleAnchor` places the title along the axis; `"end"` with `titleAngle: 0` sets a y title at the top left, over the plot, so leave room in `margins.top`.

<Example
  code={spaceSavingAxis}
  title="A space-saving axis"
  blurb="Labels above each bar, gridlines between the bands, the title at the top left."
  try={"drag a bar."}
/>

</Section>
