# Hierarchy

<Lead>A **hierarchy** is nodes that sit inside each other, declared with `structure: "hierarchy"`: one table of nodes, and a `nesting` table with one row per containment. Any mark that draws a node shape can be a container. A `contains` channel picks the rows that hold others and how they are arranged, `fit: true` on a size channel sizes a container to its contents, and `edit.hierarchy.nest` drops a node into a container or out of one.</Lead>

<ApiReference entries={api} />

<Section id="schema" title="Declaring the structure">

`structure: "hierarchy"` gives the dataset a `nodes` table and a `nesting` table. A `links` table is optional.

```js
schema: {
  structure: "hierarchy",
  tables: {
    nodes: {
      id: { type: "categorical", key: true, open: true },
      kind: { type: "categorical", domain: ["group", "note"] },
      x: { type: "quantitative", domain: [0, 100] },
      y: { type: "quantitative", domain: [0, 100] },
      w: { type: "quantitative", domain: [0, 600] },
      h: { type: "quantitative", domain: [0, 400] },
    },
    nesting: {
      child: { type: "ref" },
      parent: { type: "ref" },
    },
  },
}
```

`getData()`, `onChange` and `setData` use one array per table. A table you leave out of `data` starts empty.

<Section id="nesting" title="The nesting table">

The nesting table is declared like any other table: a field map, with a type for every column.

It needs two `ref` columns. The first names the contained node and the second names its container. Both point at the nodes table's `key: true` column, so their values are node identities. The column names are yours.

```js
nesting: {
  child: { type: "ref" },    // the contained node
  parent: { type: "ref" },   // its container
}
```

One row is one membership. A node with no row is at the top level. A node has at most one container, and cannot contain itself or any node inside it. A row from `data` or `setData` that breaks either rule is dropped with a warning, and so is a row that names a missing node.

Add any other columns you want to record about a membership. They take a `type`, a `domain` and a `default` like columns anywhere else. A row made by a drop takes each column's `default`, or the value you pass in `edit.hierarchy.nest({ defaults })`.

```js
nesting: {
  child: { type: "ref" },
  parent: { type: "ref" },
  coder: { type: "categorical", domain: ["seed", "participant"], default: "participant" },
}
```

Deleting a node removes the nesting rows that name it. Its contents move to the top level.

</Section>

<Section id="naming" title="Naming the tables">

Name the tables for your data and give each a `role`: `"nodes"`, `"nesting"` or `"links"`. A table named after its role needs no `role`, which is the short form used above.

```js
tables: {
  topics:      { role: "nodes",   fields: { … } },
  memberships: { role: "nesting", fields: { … } },
}
```

`data`, `getData()` and `setData` are then keyed `topics` and `memberships`. Marks and edits find each table by its role.

<Section id="containers" title="Containers">

A container is a row of an ordinary mark. Two channels set it up.

`contains` picks the rows that hold other nodes. `{ value: true }` is every row. `{ fn }` or `{ field }` decides per row, so groups can hold notes while notes hold nothing.

`fit: true` on a size channel sizes the row to its contents. It applies to rows that hold other nodes. The channel names a `field`, and the fitted size is written to it.

```js
rect({
  channels: {
    x: { field: "x" },
    y: { field: "y" },
    width: { field: "w", scale: null, fit: true },
    height: { field: "h", scale: null, fit: true },
    contains: { fn: (d) => d.kind === "group", padding: 12 },
  },
})
```

`scale: null` reads the column as pixels. `padding` is the room between a container's edge and its contents; see [Padding and spacing](#spacing).

A row with contents gets its fitted columns from them, so a resize edit leaves those columns alone. A row without contents keeps its own size and stays editable.

When a container loses its last child, it returns to each fitted column's `default` in the schema and keeps its top-left corner. Declare one for every fitted column; without it, the container shrinks to its padding and logs a warning.

```js
w: { type: "quantitative", domain: [0, 600], default: 130 },
```

The fitted size is in the data, so other channels can read it. The examples here place a group's name from its `h` column.

<Section id="spacing" title="Padding and spacing">

Every container keeps `padding` between its edge and its contents. The default is 10px. Give one number, or a side each; a side you leave out takes the default.

```js
contains: { fn: (d) => d.kind === "group", padding: { top: 30, right: 12, bottom: 12, left: 12 } }
```

A fitted container is sized to leave that room. A container with a size of its own moves its contents inside it.

Nodes keep 8px from their siblings. The `dodge` channel changes that: `{ value: true, gap }` sets the space, `{ fn }` or `{ field }` picks the rows that take part, and `dodge: false` lets nodes overlap. Round nodes keep the gap edge to edge. A `composite` dodges as a whole, with every part, its label included.

```js
dodge: { value: true, gap: 10 }
```

Nodes dodge their siblings: the contents of one container dodge each other, and so do the top-level nodes. When two overlap, the node you just dropped stays put and the other moves the shortest distance that clears it. When that leaves no room, the contents are packed in reading order from the top-left. A container that grows pushes its neighbours the same way, and they take their contents along. A pushed node stays inside its container's padding, or inside the plot at the top level. Where the space runs out, nodes spread as far apart as it allows.

Nodes are pushed apart on release, and when data arrives through `setData`. While you drag, they are drawn where the release will put them. Seeded data is spaced once, at the start.

<Section id="arrange" title="Arranging contents">

`arrange` on `contains` sets how a container places its contents.

| `arrange` | Contents |
| --- | --- |
| `"dodge"` | Where you drop them, pushed apart when they overlap. The default. |
| `"free"` | Where you drop them. They may overlap. |
| `"row"` | Left to right from the top-left. A row with a fixed width wraps at it. |
| `"column"` | Top to bottom from the top-left. A column with a fixed height wraps at it. |
| `"grid"` | Equal cells, the size of the largest node, `columns` to a row. |
| `"pack"` | Drawn together where you drop them, touching. |

In a row, column or grid, the order of the contents is the answer. Drag a node within its container to reorder it. Drop one into a container and it takes the nearest slot. While you drag, the other nodes open a space where it will land. On release, every node snaps to its slot.

A pack has no order. A node you drop there moves in to touch the others, and the others stay where they are. Nothing in a pack moves until you let go, so the node you aim at holds still. Round nodes pack as circles. Boxes pack as boxes, so they meet edge to edge.

`keep` sets how a dropped node moves in:

| `keep` | The node moves |
| --- | --- |
| `"distance"` | To the free spot nearest where you let go. The default. |
| `"angle"` | Straight towards the node in the middle of the pack, or away from it, until it touches. Its direction from the middle stays the same. |

Use `"angle"` when where a node sits around the middle is the answer.

`gap` is the space between slots, 8px by default. `columns` sets a grid's cells to a row. Without it, a grid fills a fixed width, or makes a square.

```js
contains: { fn: (d) => d.kind === "lane", arrange: "column", gap: 6 }
```

The order is read from the `x` and `y` columns, which hold each node's slot. A fitted container keeps its top-left corner and grows right and down. A pack is fitted round its contents.

<Section id="fixed" title="Fixed containers">

Leave `fit` off and a container keeps the size it was given. Use this for regions that are part of the question: buckets, lanes, zones. Lock them with `lock` so only the cards move. Cards stay inside the bucket's padding, and a locked row stays where it is when nodes dodge. Add `arrange` to put the cards in slots.

The answer is the nesting table: one row per card, naming its bucket.

<Section id="gestures" title="Dragging in and out">

Put `edit.hierarchy.nest()` on the mark you drag, beside `move({ mode: "relative" })`. The move carries the node. On release, the node joins the innermost container under the pointer. Released over no container, it leaves the one it was in.

While you drag, the chart shows what a release would do. The container the node would join is outlined and grows to hold it. The container it came from keeps its size while the pointer is inside it, and shrinks once the pointer leaves. Other nodes move out of the way, inside a container and at the top level. The data changes on release. Style the outline with the `target` state of `effects`.

A container stays where it is when you drag a node past it or out of it. Released against a container's edge, the node you dropped moves clear of it.

The layout eases to its new place. Nodes make room first and a container resizes after them. The node you drag stays on the pointer. Set the time with `motion: { duration }` on the spec, in milliseconds, or `motion: false` to draw each change at once. Motion is off when the reader's system asks for reduced motion.

The same `move` moves a container, and its contents travel with it.

A rule about which nodes may go where is a constraint on the nesting table. A drop the rule refuses shows no outline and leaves the data unchanged.

<Section id="external" title="Reading and setting from outside">

Containment is stored as rows, so your code reads and writes it like any other data. `getData()` returns the nesting rows and each container's fitted size.

`setData` takes the same shape. Change the nesting rows and every container re-fits. A node sent with no `x` and `y` is placed inside the container it joins, clear of the nodes already there. In an arranged container it takes the last slot.

```js
const data = chart.getData();
chart.setData({ ...data, nesting: [...data.nesting, { child: "n4", parent: "g2" }] });
```
