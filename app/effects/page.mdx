# Interaction effects

<Lead>An **effect** is transient feedback for the state of an interaction: `hovered`, `selected`, `target`, `grabbed`. Set them in `effects: { ... }` on the `Elicit` spec. Effects style a mark on top of its paint, so a data-driven `fill` or `stroke` comes back when the state ends. To draw the rules a gesture obeys, such as a clamp's bounds or a pick's reach, see [Guides](/guides).</Lead>

<ApiReference entries={api} />

<Section id="states" title="The states">

`effects` is keyed by state, and every state takes the same options.

**`hovered`** applies when the pointer is over the mark, or when a proximity pick resolves to it. Pointing at a mark and a `pick: "nearest"` edit choosing it draw the same thing.

**`selected`** applies when the mark is in the interface's selection.

**`target`** outlines the container a dragged node would join if you released it now. See [Hierarchy](/marks/hierarchy). Its default outline is `#2563eb`, padded 3px out from the edge.

**`grabbed`** applies while you drag the mark. Pass a string as shorthand for `{ filter }`.

Set a state to `false` to switch it off.

</Section>

<Section id="hover" title="Hover on an editable mark">

`hovered` applies to every editable mark by default, with or without a `pick`.
Point at a draggable bar and it responds before you press.

<Section id="mechanisms" title="The two mechanisms">

Each state paints in one of two ways, and can use both at once.

**Element props** restyle the mark itself: `filter`, `opacity`, `fill`, `stroke`,
`strokeWidth`, `cursor`. They override the mark's own paint while the state holds,
and the mark's paint returns when it ends. Every prop paints in both
[renderers](/renderers). On canvas, `filter` needs a browser whose 2D context has
`filter`; in any other it logs a warning.

**`outline`** draws an overlay on the mark's edge, above every other layer. It takes
`color`, `darken`, `fallback`, `width`, `pad`, `dash` and `opacity`, and traces
whatever shape the mark is: a ring on a circle or ellipse, the box on a rect (with its
corner radius), the segment on a tick, the path itself on an arc slice, line or
polygon. `pad` moves the trace out from the edge, and is 0 by default.

A text label gets no outline by default. The cursor change is its feedback. Set
`outline` for a state in `effects` and labels get a box around the text in that state.

The outline's colour comes from the mark. With the default `color: "auto"`, it is
the mark's fill, or its stroke when the fill is missing or near-white, darkened by
`darken` (0.6 for `hovered`, 1.5 for `selected`; a negative value lightens). A teal bar
lights up in deep teal and a coral dot in deep coral. `"fill"` or `"stroke"` reads
that paint only. A CSS colour fixes the outline to that colour. A function
`(color, node) => string` receives the derived colour and returns the one to paint.
`fallback` is used when the mark's paint can't be read, such as a gradient fill.

Element props follow the mark wherever it goes. An outline copies the mark's
rotation: rotate a mark with an [`angle` channel](/marks/point#angle) and its outline
turns with it. Proximity picking measures the same rotated shape, so the mark that
lights up is the mark a drag grabs.

<Example
  code={theTwoMechanisms}
  title="Element props, and outline"
  blurb="Left restyles the dot; right leaves it alone and rings it. Both keep the fill the data gives it."
  try={(
    <>
      <b>Hover</b> both charts. The dots' own colours never change.
    </>
  )}
/>

</Section>

<Section id="precedence" title="Hovered and selected together">

`selected` outranks `hovered`: a selected mark draws as selected while you hover it.
Give the two different weights. `hovered` shows which mark a gesture would take, and
`selected` shows which one you picked.

The interface holds the selection, separate from the data: `edit.select` writes no
`selected` field. See [Editing a selected item](/marks/legend#dynamic-target).

<Example
  code={hoveredThenSelected}
  title="A light hover, a firm selection"
  blurb="Alt-click selects, so a plain click still drags. A shallow shade on hover, a deep thick one on selection."
  try={(
    <>
      <b>Alt-click</b> a bar to select it, <b>hover</b> the others, <b>drag</b> any.
    </>
  )}
/>

</Section>

<Section id="mute" title="Highlight and mute">

A state's own options are its highlight: how a mark in that state looks. `others` is its mute. It restyles every mark that is in no state, for as long as the state holds on at least one row. It takes the element props `opacity`, `filter`, `fill`, `stroke` and `strokeWidth`.

Every state takes `others`. On `selected` it gives a highlight that stays until you clear the selection.

<Example
  code={muteTheRest}
  title="Select one, fade the rest"
  blurb="selected keeps its default outline. others fades the unselected bars."
  try={(
    <>
      <b>Click</b> a bar to select it. Click it again to clear.
    </>
  )}
/>

Setting `others` on `hovered` makes hover apply to the row: every mark that draws the row lights up, on view-only marks too.

</Section>

<Section id="neighbours" title="Neighbours in a network">

`neighbours: true` extends a state's highlight to the rows linked to it. Hover a node and its links light up; hover a link and its two nodes do. In a [hierarchy](/marks/hierarchy), a node also lights everything nested inside it.

`neighbours` applies to network and hierarchy datasets, where a `ref` column links one row to another. On a dataset with a single table it does nothing and logs a warning.

<Example
  code={hoverAFactor}
  title="What a factor touches"
  blurb="neighbours lights the hovered factor's links. others fades every other factor and link."
  try={(
    <>
      <b>Hover</b> a factor, then a link.
    </>
  )}
/>

</Section>

<Section id="link" title="Hover across charts">

`hovered` takes one more option, `link`. With `link: true` the chart's hover is the dataset's: the hovered row lights up in every chart on that dataset, and the other rows fade. It is on by default when two or more charts share a dataset. See [Linked hover](/dataset#hover).

</Section>

<Section id="off" title="Switching a state off">

`false` disables a state. Turn one off where the mark reads clearly on its own, such
as a dense grid where an outline per cell adds noise.

<Example
  code={switchingAStateOff}
  title="Feedback only on drag"
  blurb="hovered: false and selected: false; only the drag reads back."
  try={(
    <>
      <b>Hover</b> a bar, then <b>drag</b> it.
    </>
  )}
/>

</Section>

<Section id="default" title="Hover and proximity, one signal">

A `pick: "nearest"` drag draws two things. The ring is the pick's `catchment`, a
[guide](/guides#parts) on the edit. The outline on the resolved dot is the `hovered`
effect — the same one you get by pointing straight at a mark.

<Example
  code={proximitySelect}
  title="Proximity select"

</Section>
