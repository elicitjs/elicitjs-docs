# Theming & style

<Lead>The **theme** holds every default colour, font and affordance token. Pass a partial `theme` on `Elicit` or on any widget. It deep-merges over the built-in defaults, so you name only what you change. A per-datum paint channel (`fill`, `stroke`) wins over any theme token. A theme can also set [effects](/effects) defaults, and `effects` on the spec overrides them. Twenty [named themes](/theming/themes) ship with the library: `theme: "nyt"` restyles a whole chart from one word.</Lead>

<ApiReference entries={api} />

<Section id="survey" title="A themed instrument">

`themes.survey` is a built-in theme for survey widgets. Pass it to any widget to restyle the answer ink and the chrome. The behaviour stays the same. It also sets the widgets' [design](/widgets#designs): `survey` draws outlined boxes, `surveyBlocks` filled blocks and `surveyLines` hairlines. The widget tokens are `theme.widget`, where `design` names the design and the rest are the colours and sizes it reads.

<Example
  code={surveyTheme}
  title="The survey theme"
  blurb="One object — themes.survey — restyles the ink, the chrome and the design."
  try={"move across the options, click to answer — the look is the only change."}
/>

</Section>

<Section id="dark" title="Dark mode">

The `background` token paints the chart's own surface, margins included. `themes.dark` uses it with light ink, light labels and a slate grid, so it needs no host CSS. The same spec renders light or dark by changing only the `theme`.

<Example
  code={darkMode}
  title="themes.dark"
  blurb="A slate backdrop with light ink and chrome — the chart paints its own surface."
  try={"drag a bar — the interaction is identical, only the palette is dark."}
/>

</Section>

<Section id="tokens" title="A theme on a plain chart">

A theme is a plain object, so it deep-merges cleanly. `ink` is the primary mark colour, used by every mark with no paint channel of its own. `axis` and `grid` style the chrome. A token you name changes, and a token you leave out keeps its default.

  title="Per-chart theme"
  blurb="ink recolours the bars; axis/grid restyle the chrome. Drag a bar — the value axis still works."
  try={"drag a bar up or down."}
/>

</Section>

<Section id="chrome" title="Axes, grids and the plot panel">

The `axis` tokens style every axis: `stroke` and `strokeWidth` for the spine and ticks, `line: false` to drop the spine, `tickSize` (0 for none) and `tickPadding` for the gap to the label, `labelAngle` to turn the labels. Each is also an [`axis()` option](/marks/axes#styling), and the option wins. `grid.show` adds gridlines without a `grid()` element. `panel` paints the plot area under the grid and can frame it; `background` covers the margins too. `bandPadding` sets the gap between bars.

<Example
  code={chromeTokens}
  title="A grey panel, white gridlines"
  blurb="panel, grid, axis and bandPadding tokens, and nothing else."
  try={"drag a bar."}
/>

`axis.discrete` and `axis.continuous` override any axis token for axes of that kind. Use them to drop the spine on the value axis and keep it under the categories. `grid.show: "value"` grids the axis the value runs along: the continuous one, or y when both are. `grid.zero` draws an emphasised line at 0.

<Example

  title="Per-kind axes and a zero rule"
  blurb="A spine under the categories, none on the values, a dotted value grid and a rule at 0."
  try={"drag Q2 above zero."}
/>

</Section>

<Section id="typography" title="Typography">

`font.family` sets the chart's typeface. `null` inherits the page's. `title`, `subtitle` and `caption` each take `fontFamily`, `fontStyle`, `fontWeight`, `fontSize` and `fill`, so a headline can be a serif over sans-serif labels. The axis takes `fontFamily` and `fontWeight` for its labels and `titleFill`, `titleFontSize` and `titleFontWeight` for its title. A [`text`](/marks/text) mark takes `fontWeight`, `fontStyle` and `fontFamily`, each a constant or a channel.

<Section id="titles" title="Titles and captions">

`title`, `subtitle` and `caption` on the `Elicit` spec draw text above and below the plot, left-aligned with it. They reserve space the way a legend does: the chart keeps its declared `width` and `height`, and the plot shrinks to make room. The theme's `title`, `subtitle` and `caption` tokens style them, each with `fill`, `fontSize`, `fontWeight`, `fontFamily` and `fontStyle` (see [Typography](#typography)). A token with no `fill` takes the axis label colour, so the titles follow a dark theme.

<Example

  title="A titled chart with a caption"
  blurb="title, subtitle and caption on the spec; theme.title and theme.caption recolour two of them."
  try={"drag a bar — the plot sits between the title block and the caption."}

<Section id="precedence" title="Overrides & precedence">

The most specific setting wins. A per-datum channel or mark option beats `theme.marks[name]`, which beats the theme token (`ink`), which beats the renderer default. A theme sets the overall look, and a single mark can still override it.

<Example
  code={perMarkOverride}
  title="Per-mark override"
  blurb="ink colours the bars; theme.marks.point overrides just the dots."
  try={"drag a dot — its colour comes from theme.marks.point, not ink."}
/>

</Section>

<Section id="app-wide" title="App-wide defaults">

Call `setTheme(partial)` once at startup to theme a whole application. Every chart built afterwards inherits it, and a chart's own `theme` layers on top. `setTheme(themes.survey)` makes the survey look the default. `setTheme(null)` resets to the built-in theme.

```js
import { setTheme, themes } from "elicit-js";

setTheme(themes.survey);          // app-wide default
// …every Elicit(...) after this inherits it
setTheme("economist");            // or a named theme by name
setTheme({ ink: "#4f46e5" });     // or just a token or two
```

</Section>
