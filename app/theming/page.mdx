# Theming & style

<Lead>Every default colour, font, and affordance token lives in one place — the **theme**. Pass a partial `theme` on `Elicit` (or on any widget) and it deep-merges over the built-in defaults, so you name only what you change. It sits alongside, and under, the two style hooks you already have: a per-datum paint **channel** (`fill`, `stroke`) still wins over any theme token, and the [effects](/effects) layer still owns interaction feedback. Seventeen [named themes](/theming/themes) ship with the library — `theme: "nyt"` restyles a whole chart from one word.</Lead>

<Section id="survey" title="A themed instrument">

`themes.survey` is a built-in professional look. Pass it to any widget and the answer ink, the chrome, and the affordance rings/track/labels all follow it — the behaviour is unchanged, only the style.

<Section id="dark" title="Dark mode">

Yes — a theme can produce a fully dark chart. The `background` token paints the chart's own surface (svg / canvas, margin band included), so `themes.dark` is self-contained: light ink, light labels, a slate grid, no host CSS required. The same spec renders light or dark; only the `theme` changes.

<Example
  code={darkMode}
  title="themes.dark"
  blurb="A slate backdrop with light ink and chrome — the chart paints its own surface."
  try={"drag a bar — the interaction is identical, only the palette is dark."}
/>

</Section>

<Section id="tokens" title="A theme on a plain chart">

A theme is plain data — no functions, no classes — so it merges cleanly. `ink` is the primary mark colour (every mark with no explicit paint channel reads it); `axis` and `grid` are the chrome. Name a token and it changes; leave one out and it inherits the default.

<Example
  code={perChartTheme}
  title="Per-chart theme"
  blurb="ink recolours the bars; axis/grid restyle the chrome. Drag a bar — the value axis still works."
  try={"drag a bar up or down."}
/>

</Section>

<Section id="chrome" title="Axes, grids and the plot panel">

The `axis` tokens style every axis: `stroke` and `strokeWidth` for the spine and ticks, `line: false` to drop the spine, `tickSize` (0 for none) and `tickPadding` for the gap to the label, `labelAngle` to turn the labels. Each is also an [`axis()` option](/marks/axes#styling), which wins. `grid.show` adds gridlines you did not ask for. `panel` paints the plot area under the grid and can frame it; `background` covers the margins too. `bandPadding` sets the gap between bars.

<Example
  code={chromeTokens}
  title="A grey panel, white gridlines"
  blurb="panel, grid, axis and bandPadding tokens, and nothing else."
  try={"drag a bar."}
/>

`axis.discrete` and `axis.continuous` override any axis token for axes of that kind. That is how a house drops the spine on the value axis and keeps it under the categories. `grid.show: "value"` grids the axis the value runs along: the continuous one, or y when both are. `grid.zero` draws an emphasised line at 0.

<Example
  code={perKindAxes}
  title="Per-kind axes and a zero rule"
  blurb="A spine under the categories, none on the values, a dotted value grid and a rule at 0."
  try={"drag Q2 above zero."}
/>

</Section>

<Section id="typography" title="Typography">

`font.family` sets the chart's typeface; null inherits the page's. `title`, `subtitle` and `caption` each take `fontFamily`, `fontStyle`, `fontWeight`, `fontSize` and `fill`, so a headline can be a serif over sans-serif labels. The axis takes `fontFamily` and `fontWeight` for its labels and `titleFill`, `titleFontSize` and `titleFontWeight` for its title. A [`text`](/marks/text) mark takes `fontWeight`, `fontStyle` and `fontFamily`, each a constant or a channel.

<Example
  code={typography}
  title="A serif title over sans-serif labels"
  blurb="font, title, subtitle and axis tokens, and a bold text mark."
  try={"drag a bar."}
/>

</Section>

<Section id="titles" title="Titles and captions">

`title`, `subtitle` and `caption` on the `Elicit` spec draw text above and below the plot, left-aligned with it. They reserve layout space the way a legend does: the chart keeps its declared `width` and `height`, and the plot shrinks to make room. The theme's `title`, `subtitle` and `caption` tokens style them, each `{ fill, fontSize, fontWeight }`. A token with no `fill` takes the axis label colour, so the titles follow a dark theme.

<Example
  code={titledChartWithACaption}
  title="A titled chart with a caption"
  blurb="title, subtitle and caption on the spec; theme.title and theme.caption recolour two of them."
  try={"drag a bar — the plot sits between the title block and the caption."}
/>

</Section>

<Section id="precedence" title="Overrides & precedence">

Resolution is layered, most specific first: a per-datum **channel** or option beats `theme.marks[name]`, which beats the theme **token** (`ink`), which beats the renderer default. So a theme sets the family look while a single mark can still opt out.

<Example
  code={perMarkOverride}
  title="Per-mark override"
  blurb="ink colours the bars; theme.marks.point overrides just the dots."
  try={"drag a dot — its colour comes from theme.marks.point, not ink."}
/>

</Section>

<Section id="app-wide" title="App-wide defaults">

To theme a whole application without threading `theme` through every chart, call `setTheme(partial)` once at startup — every chart built afterwards inherits it, and a chart's own `theme` still layers on top. `setTheme(themes.survey)` makes the survey look the default; `setTheme(null)` resets to the built-in.

```js
import { setTheme, themes } from "elicit-js";

setTheme(themes.survey);          // app-wide default
// …every Elicit(...) after this inherits it
setTheme("economist");            // or a named theme by name
setTheme({ ink: "#4f46e5" });     // or just a token or two
```

</Section>
